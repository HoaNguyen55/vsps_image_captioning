======================================================================================================================
0. BOTTOM LINE
======================================================================================================================
- The literal "F1 minus frontier F1 at the caption's count" is NOT count-neutral in RLOO. The frontier prices a class at
  0.586 TP; within an image the policy's extra classes are right only 0.48 [0.44, 0.52]. So every frontier residual
  pushes toward FEWER objects (-0.11 to -0.51 SD/class), and the power-law forms pay captions that name no object
  ("say-nothing" hacking; 10-14% of step-0 rollouts). The literal forms also import test-fitted constants into training.
- Use a count-stratified RLOO baseline (CS) instead. Its count gradient is exactly 0 (E grad = sum_m P(m) grad E[F1|M=m]),
  it needs no constants, and inventories win 0.3-0.7% of groups (plain F1: 3-6%). Cost: 22% of groups lose object signal.
- One-step cross-fit proxy: +1.4 to +1.8 count-matched F1 over CIDEr-only. SFT on the same 5-ref information (mr5assist)
  sits on the frontier, so P(test pass) ~25%. Novelty low-moderate. 4.0 GPU-h first look; ~18 more for a 3-seed claim.

======================================================================================================================
1. PROBLEM AND HYPOTHESIS
======================================================================================================================
PD-2: no method beats the count frontier at matched count. An object reward in CN-RLOO (R9 C4 P-A) can raise F1 just by
naming more classes, i.e. by moving ALONG the frontier, as UPE-MBR and PLAN-F1 did.
H1: CN-RLOO with advantage rloo(CIDEr-D)/s_C + w CS(F1)/s_O (w = 1) raises matched-count object F1 over the
CIDEr-only control (35_e) at an unchanged count. Falsifiable predictions:
- P1 (dev300): cm(M4) - cm(35_e) >= +1.0 (cm = count-matched dF1 vs the vote-top-k control, sec. 4c).
- P2: |classes/caption(M4) - classes/caption(35_e)| <= 0.15.
- P3 (test, 3 seeds): pooled frontier residual F1 - F^1(m) of M4 minus the control >= +1.0, 95% CI excluding 0.
- P4 (optional plain-F1 arm): the count rises (>= +0.15) and the residual stays within +-1.0.
H0 (frontier invariance): any RL object term moves only along the frontier; M4's matched-count gain <= +0.5, CI over 0.

3b. Q1: IS THE PER-CAPTION RESIDUAL WELL DEFINED? Only as a within-group count price, and that price is wrong.
  (i) Level: TP1 is a corpus mean, and TP at a given count differs by image. RLOO (no std norm, rl_reward.rloo) cancels
      every per-image term, so only the within-image count slope acts.
  (ii) Slope: the frontier is a BETWEEN-system law (one point per trained system; b from 2 anchor groups at m = 1.78
      and 3.15), but RLOO contrasts samples WITHIN an image.
      - Within-image marginal TP per extra class (fixed-effects slope): 0.479 [0.436, 0.525] | 0.472 [0.426, 0.517],
        vs the frontier price 0.586.
      - Pairwise steps 0->1 / 1->2 / 2->3: 0.61 / 0.52 / 0.38 | 0.58 / 0.48 / 0.41.
      - Precision at caption count 1 / 2 / 3 / 4: 68 / 63 / 54 / 50% (dev).
      The between-system curve does not give the within-image price (an ecological-inference error).
  (iii) Extrapolation: the power law is used at integer counts 0..5, outside its fit range. The first class costs
      0.909 TP, so naming nothing is rewarded.
  (iv) Jensen: on dev rollouts, E f(M) = 1.223 vs f(E M) = 1.278 TP/img. As an ENDPOINT, the residual must come from
      corpus means; prereg_ladder_check.residual already does this.
  (v) Leakage: TP1, M1, b, c0 and c1 were fitted on KTVIC TEST runs, and the cross-system frontier cannot be refitted
      on dev300 (fuse2 trained on those images).
  Count gradient of the advantage, SD per extra class (fixed-effects slope; raw 95% CI excludes 0 for every object term
  except CS; CIDEr: point estimate only):
  | term | dev | train | object-free rollouts vs group mean (dev / train) |

  | CIDEr-D (35_e reward) | +0.21 | +0.06 | n/a |

6. RISKS AND FIT WITH PD-2
======================================================================================================================
- Information ceiling: the reward reads the same 5 refs that put mr5assist on the frontier, so H0 is the likely outcome.
  The kill after 4 GPU-h bounds the cost.
- Signal loss: CS gives no object signal in 22-23% of groups and |A| is 0.62 SD, so the run may be under-moved. No
  fallback is registered, on purpose; the EMA-slope form TP - lambda_hat M (lambda re-estimated within groups each
  step) would need a new decision.
- Count drift: the CIDEr term still moves the count (+0.21 SD/class on dev). The control shares that drift, and the
  endpoint is relative to the control and count-matched.
- Single appends (H4) win 8% at w = 1. The CIDEr guard (about -30 per append on the proxy) and mentions bound them.
- Reference style: KTVIC-union gains can be typicality. The OpenViIC panel residual is the truth-side check.
- Proxy limits: the proxy is one-step and on the 2-ref scale; its effect sizes are proxy sizes.
Fit: strengthens the METHODOLOGY pillar. It turns PD-2's matched-count endpoint into a training signal, and it shows
that a between-system frontier mis-prices the within-image contrast, a general caution against debiasing a reward with
a fitted curve. It is the only RL arm whose success criterion is PD-2's primary endpoint. A pass would be the first
method above the frontier; a null shows frontier invariance holds even under an RL reward that targets it.
