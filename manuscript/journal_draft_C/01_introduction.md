## 1. Introduction

Open multimodal large language models (MLLMs) can caption images in Vietnamese with no task training. Their zero-shot captions still score far below fine-tuned systems on the Vietnamese benchmarks KTVIC [@Pham2024KTVIC], UIT-OpenViIC [@Bui2023OpenViIC; @Bui2026OpenViICJournal] and the Vietnamese part of XM3600 [@Thapliyal2022XM3600]. A companion study by the same group (the scoring study, under review) shows that reference conventions, such as the absence of sentence-final punctuation in KTVIC references, move CIDEr-D [@Vedantam2015CIDEr] substantially under Vietnamese scoring pipelines. Part of the zero-shot gap is therefore a matter of matching the references' conventions rather than of content.

**Why Vietnamese captioning is a low-resource problem.** Vietnamese has a large speaker community but, like most of the world's languages, few annotated resources compared with English [@Joshi2020StateFate]. For captioning, the gap is concrete. The public general-domain Vietnamese sets are few and far smaller than English ones such as COCO, and each was built for its own domain and reference style [@Lam2020UITViIC; @Pham2024KTVIC; @Bui2023OpenViIC; @Hoang2026HDUCap]; other Vietnamese sets target a single domain, such as healthcare [@Nguyen2022VieCap4H] or scene text [@Nguyen2026ViTextCaps]. The memory this study builds from two of them holds 10,501 images (Table 3), against 112,255 for the English memory built from COCO alone (Section 8.1); no claim about memory size is made across languages. Multilingual systems that reach Vietnamese often rely on image-text data or retrieved captions translated from English, which brings translation artefacts into the output [@Vu2025VELVET; @Ibrahim2025CONCAP]; a recent benchmark of open VLMs for Urdu and Arabic captioning is likewise built on translated captions [@Hussain2026SciRepLVLM]. Vietnamese text also has to be word-segmented before n-gram scoring, because spaces separate syllables rather than words [@Vu2018VnCoreNLP]. So a method that uses the little in-language data that exists, without training on it, is attractive, and its gains need careful attribution.

This matters in practice. Fine-tuning a captioner needs GPU time, training code and a licence to train on the captions; a retrieval prompt reuses an existing captioned training set as a memory, at inference time, on one 24 GB GPU. But if a reported gain comes from showing the model any in-domain caption, a cheaper prompt with fixed or random examples would do as well, and a memory from another domain might not help.

**Retrieval in-context captioning** is a cheap way to close a style gap. For each query image, the captions of its nearest training images are put into the prompt as text examples, and the model is asked to write in the same way. Related work in English and in multilingual settings reports large CIDEr gains from retrieved or well-chosen examples [@Yang2023ICLConfig; @Ramos2023LMCap; @Rebelo2025RSCap]. Studies of in-context configurations in English compare similarity-based selection with random selection, mostly for models that see the example images as well as their captions [@Yang2023ICLConfig; @Li2025UnveilingICL]. OpenFlamingo [@Awadalla2023OpenFlamingo], using retrieval-based in-context example selection [@Yang2022PICa] as Flamingo did [@Alayrac2022Flamingo], reports that retrieved image-caption examples beat random ones on COCO, while on Flickr-30K they did worse at 0 and 4 shots. Our English arm is therefore a replication of a known English pattern under different conditions (text-only example captions, a frozen configuration and a one-look test), not a new finding. For Vietnamese with text-only example captions, the question remains which of two effects a gain over zero-shot prompting reflects:

- the effect of **retrieval**: examples that describe similar images;
- the effect of seeing **any in-domain captions**: examples that only show the dataset's style.

This study measures the first effect against the second. Our main control, `rand`, shows the model the same number k of captions from the same memory, chosen at random for each image. A second control, `fix`, shows one fixed set of k captions for every image. `zs` is plain zero-shot prompting. If retrieval helps only through style, `ret` and `rand` should score about the same.

We also track what retrieval may cost in faithfulness. Retrieved captions describe other images, and a model can copy their objects into its own caption [@Li2024RetrievalRobustness]. We therefore registered a second prediction on **count-matched object precision** (defined in a second companion study, the object-precision study, under review). It compares a caption's object mentions with those of the same model's zero-shot caption at an equal number of mentions, so that a longer caption is not penalised merely for naming more objects.

The study was preregistered in three stages, each committed before the data it uses reached the GPU server used for decoding:

1. exploration on development set A, which picks one configuration per model;
2. a one-look confirmation on development set B, with a registered gate;
3. a one-look test on each of two test sets.

The test registration fixed the estimands, the smallest effect size of interest (SESOI, +2.0 stripped CIDEr-D points), the decision rules, the wording each outcome allows, and the reporting of failures. We report every registered verdict as computed.

A separately registered English arm then carried the frozen Vietnamese configurations, with translated prompts and no English tuning, to the COCO Karpathy test [@Lin2014COCO; @Karpathy2015Split] and NoCaps val [@Agrawal2019NoCaps]. Each English set was also looked at once. English and Vietnamese results are reported side by side, each within its own language and scorer, and no cross-language difference is computed.

**Contributions.**
- **A controlled comparison.** Retrieved, random, fixed and zero-shot examples are compared for Vietnamese captioning with two open MLLMs, each at its frozen configuration. The study was preregistered in three stages with one look per test set. The random control is drawn at equal k from the same memory, which separates the effect of retrieval from that of in-domain style.
- **In domain, in two languages.** The registered primary passed on OpenViIC test (P1) and on the COCO Karpathy test (P1-EN). In both languages the gain is carried mainly by Qwen2.5-VL; for InternVL3 it was not detected on OpenViIC test, and its COCO row (a reported row, not registered) is below zero. InternVL3's registered arm includes a verifier-based deletion step (Section 3.4), which is part of the estimand. On OpenViIC test, neither model lost count-matched object precision beyond the registered floor.
- **Outside the memory's source.** The gain was not detected on XM3600 Vietnamese (XM-a FAIL; the XM3600 prediction is not confirmed). On NoCaps val its CI lies above zero but its point stayed below the SESOI, under a rule stricter than XM-a's (S-NC FAIL), and the transfer claim is not made.
- **A full record.** Every registered row, deviation and exposure of test data is reported, including the failures. Scores, image ids, hashes, registrations and code are released; captions and per-image ledgers are not.

The paper does not propose a new method. Sections 2–5 give related work, method, data and the registered plan; Section 6 the Vietnamese results, ending with a labelled development-set analysis; Section 7 the disclosures; Section 8 the English arm; Sections 9–10 the limitations and conclusions.
