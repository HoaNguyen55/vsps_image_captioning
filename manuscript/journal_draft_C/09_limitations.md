## 9. Limitations and threats to validity

### 9.1 Limitations

- **Two backbones, and the effect is carried by one.** In both languages the in-domain gain is carried mainly by Qwen2.5-VL. For InternVL3 the gain was not detected on OpenViIC test, and on COCO its row is below zero (−1.64 [−2.79, −0.49]). The dev-only ablations of Section 6.8 trace part of this dependence to the frozen deletion step, but outside in-domain Vietnamese InternVL3's τ = −∞ row is not detected either (XM-test2500, COCO, NoCaps). With two backbones, the study cannot say which property of a model predicts the gain. The pooled estimand averages two backbone-plus-configuration pairs that differ in k, order, tail and τ, so it is not an effect for a typical MLLM.
- **Out of the memory's source, the registered predictions did not pass.** On XM3600 Vietnamese the gain was not detected (XM-a FAIL). On NoCaps val the CI lies above zero but the point stayed below the SESOI (S-NC FAIL), under a rule that was fixed after XM-a was known and is stricter than XM-a's. Neither memory holds captions of the target set. Memory source and test set change together across these rows, and no test varied the memory on fixed test images, so the source match is confounded with the test set. The "domain coverage" reading of Section 8.4 is post hoc and untested, and its per-domain rows have overlapping CIs.
- **The metric is reference-based.** CIDEr-D rewards matching the references' wording. In Vietnamese, the stripped column removes the trailing-period effect, and the PTB column agrees with it. Still, part of any `ret` − `rand` gain may be closer wording of image-specific content rather than better content. The study has no human judgments; by design, it uses existing data and labels only.
- **Object measures depend on the matcher and the gold.** On OpenViIC, gold objects come from the union of the references, so a correct object that no reference names counts as an error. On XM3600, the verified labels cover only the mapped classes. The English arm registered no object-precision prediction.
- **The memory and test sets come from related sources.** KTVIC and OpenViIC share images. We removed byte-identical and near-duplicate images between the memory and every protected set, and excluded the near-duplicates of the tuning set from the primary set. Overlaps below the pixel rule's thresholds would not be caught. The same rule protected the English sets.
- **One test look, one machine, one run, one random draw.** Each test set was decoded once with greedy decoding. The CIs capture image sampling conditional on one seeded `rand` assignment per image and on full-set document frequencies; they do not include the variation from drawing other random examples, or run-to-run variation. Decode-parity checks on the same machine and software stack found no run-to-run variation on development data (52/52 identical captions per backbone; supplement, "Test-run operations", and Table S14).
- **The backbones' training data are not fully disclosed.** The Qwen2.5-VL report [@Bai2025Qwen25VL] describes its training data by category (image captions, interleaved image-text, OCR data that include Vietnamese); in our reading it does not name COCO, NoCaps or a Vietnamese caption set. The InternVL3 report [@Zhu2025InternVL3] builds on the corpora of InternVL2.5, whose report lists COCO captions, Open Images captions and TextCaps among its training data [@Chen2024InternVL25]. COCO images and captions, and Open Images images like those of NoCaps, may therefore have been seen in training, at least by InternVL3. The equal-k `rand` control removes contamination that `ret` and `rand` share, but not contamination that interacts with retrieval (retrieved captions cueing memorised references). "Training-free" means no task training in this study; this is a desk check of public reports, not an audit.
- **No priority claim.** Retrieval in-context captioning has been studied before (Section 2). This paper's contribution is the controlled, preregistered comparison, not the method.

### 9.2 Threats to validity

**Internal validity.** `ret`, `rand` and `fix` share one prompt template, one k and one decoder, and differ only in which captions are shown; `rand` is seeded per image. Rule L did not fire on OpenViIC test (0.074, 0.039) or COCO (0.019, 0.019), and the source-dataset share of shown examples is near one for every arm (Table S6), so the contrast is not between in-domain and out-of-domain style. One threat remains, a design limitation of the registered estimand: InternVL3's deletion step acts after decoding and treats `ret` and `rand` captions differently, because they introduce different numbers of neighbour-only objects (Section 6.8). On OV-test it lowered CIDEr-D and did not improve CHAIR_i or ΔP_cm (Section 6.6); the registered τ = −∞ secondary is printed beside every τ = 0.10 row for this reason.

**Construct validity.** CIDEr-D measures agreement with the references, in Vietnamese on word-segmented text and in English on PTB tokens; the two scales are not comparable. Count-matched object precision guards against a gain bought by copying wrong objects; it held for both backbones on OpenViIC test and was not registered in English.

**External validity.** The result applies in domain, on two benchmarks in two languages, with two 7–8B open MLLMs and a memory of one or two benchmarks' training captions. It does not apply out of the memory's source (XM3600, NoCaps), and it is untested for other model families or sizes, sampled decoding or prompts with example images. The English arm reused Vietnamese-chosen configurations, so it is a conservative transfer test, not an estimate of the best English setting.

**Statistical conclusion validity and researcher degrees of freedom.** Every decision uses a registered rule on a paired image bootstrap with a fixed SESOI that was a planning value, carried to English without recalibration (Sections 5.2 and 5.4). Per-backbone, per-domain and development rows carry unadjusted CIs and no claim, and no p-values are reported. Configurations were frozen on development data and each test set was looked at once. Three choices were made with knowledge of earlier results and are disclosed (Sections 6.8, 7.4 and 8.5): the English registration followed the Vietnamese verdicts, the stricter NoCaps rule followed XM-a, and two of the six ablation τ points were known.

### 9.3 Reproducibility

Every model snapshot, processor setting, environment, prompt template, list and code file is pinned by sha256, and each decision file records the hashes of the ledgers it read, the registration hash and the code commit. Scores, image ids and hashes are released; captions, example files, embeddings and per-image ledgers are not. A third party can re-run the study from the public datasets with the released code, lists and seeds on one 24 GB GPU (9.59 GPU-hours for the Vietnamese test, 13.22 for the English one) and check each run against the released hashes.
