## 3.2 The five references of an image come from one writer

KTVIC's paper describes an interface in which one annotator types all five captions of an image (Pham et al., 2024, §3.2, Fig. 5). Metrics built on multiple references assume that the references are independent descriptions. We test the assumption directly with an exchangeability statistic on object mentions. Take every object class that exactly two of an image's five references name (a "doubleton"). If the five slots were exchangeable, the two naming references would be adjacent (slots *i* and *i*+1) with probability 4/10 = 0.40.

On the test split the observed adjacent share is 0.7102 [0.6696, 0.7518] over 566 doubletons (z = 15.07 against the null of 0.40)<!-- src: .session_backup/2026-10-14/r11_verify/c3_n2_exchangeability_all_datasets.json :: k5_exchangeability_audit.ktvic_test_objects_in.adjacent_share ; adjacent_share_ci95 ; total_doubletons ; adjacent_share_z_vs_null ; adjacent_share_null -->. The training split shows the same pattern, 0.6673 [0.6499, 0.6852]<!-- src: .session_backup/2026-10-14/r11_verify/c3_n2_exchangeability_all_datasets.json :: k5_exchangeability_audit.ktvic_train_objects_in.adjacent_share ; adjacent_share_ci95 -->, as does dev300, 0.631 [0.5649, 0.6962]<!-- src: .session_backup/2026-10-14/r11_verify/c3_n2_exchangeability_all_datasets.json :: k5_exchangeability_audit.ktvic_dev300_objects_in.adjacent_share ; adjacent_share_ci95 -->. Object-set similarity between consecutive references (lag 1) exceeds the mean similarity at lags 2–4 by 0.135 [0.1178, 0.1538] in Jaccard index<!-- src: .session_backup/2026-10-14/r11_verify/c3_n2_exchangeability_all_datasets.json :: k5_exchangeability_audit.ktvic_test_objects_in.jac_lag1_minus_mean_lag2to4 ; jac_diff_ci95 -->. The references read as a chain of paraphrases, each written with the previous one in view.<!-- FIGURE TODO (main, 2026-10-19): place B2's B-only adjacency figure here (.session_backup/2026-10-18/paperA_tasks/B2/fig2_adjacency_Bonly.pdf), never the variant with Paper-A comparators (PD-6). Insert only after the A-verifier marks B2 VERIFIED; until then no B2 number enters the text. -->

Two consequences follow for evaluation.

- **The references are one writer's view, five times.** A leave-one-out comparison of each reference against the other four gives object P / R / F1 of 85.33 / 46.90 / 60.50<!-- src: data/results/human_parity.json :: 1v4.human.P ; 1v4.human.R ; 1v4.human.F1 -->. Because all five references share one writer, this is a within-writer consistency figure, not a human ceiling; we do not compare systems to it as "human parity".
- **Five references are worth less than five.** The object gold of an image is the union of its references. Under a chain of paraphrases, the extra references add fewer new objects than independent captions would, so recall against the union understates what a caption gets right about the image. Section 5.4 measures this with a second caption panel.

## 3.3 No punctuation in the references, and what one period costs

None of the 2,790 test references and none of the 18,845 training references ends with a period<!-- src: .session_backup/2026-10-14/r11_verify/c1_b1_b6_reproduction.json :: B5_L5_cider_punct_and_uitviic_chair.ktvic_period_audit.test_refs_ending_period ; train_refs_ending_period -->. A system fine-tuned on KTVIC learns this: none of the 558 test outputs of our response-only P1 (seed 42) ends with a period, while 557 of the 558 zero-shot outputs of the same backbone do<!-- src: .session_backup/2026-10-14/r11_verify/c1_b1_b6_reproduction.json :: B5_L5_cider_punct_and_uitviic_chair.ktvic_period_audit.p1assist_s42_short_ending_period ; zeroshot_short_ending_period -->.

**Mechanism.** CIDEr-D weights each n-gram by its inverse document frequency over the reference set and divides the dot product by the norms of the candidate and reference vectors. An n-gram that contains "." has document frequency zero in KTVIC's references. It cannot match, but it still enters the candidate's norm, so every period lowers the score of the whole caption.

**Size.** Appending one "." to each output of P1 (seed 42) lowers CIDEr-D from 148.66 to 113.49 against the five references, a change of −35.17 (−23.66%)<!-- src: .session_backup/2026-10-14/r11_verify/c8_l5_d1_d3a_cpu_audit.json :: l5_d1_punct_idf_law|ktvic_test_k1_to_k5_curves|p1assist_s42-short|first_k|k=5|cider_strip ; cider_add_period ; d_abs ; d_rel_pct -->. Against one reference the change is −36.17 (−16.73%)<!-- src: .session_backup/2026-10-14/r11_verify/c8_l5_d1_d3a_cpu_audit.json :: l5_d1_punct_idf_law|ktvic_test_k1_to_k5_curves|p1assist_s42-short|first_k|k=1|d_abs ; d_rel_pct -->. The absolute loss stays near 35 points as references are added, while the relative loss grows, because the score itself falls with more references. In the other direction, the zero-shot outputs score 28.98 as written and 33.30 with their final periods stripped<!-- src: .session_backup/2026-10-14/r11_verify/c8_l5_d1_d3a_cpu_audit.json :: l5_d1_punct_idf_law|ktvic_test_k1_to_k5_curves|zeroshot-short|first_k|k=5|cider_add_period ; cider_strip --> (the committed score is 28.98<!-- src: data/results/zeroshot-short.json :: results[0].scores_scaled_x100.CIDEr -->). Part of the gap between zero-shot and fine-tuned systems on KTVIC is therefore punctuation, not content.

**UIT-ViIC follows the opposite convention.** Its references almost all end with a period: 1,133 of its 1,155 test references (98.10%)<!-- src: .session_backup/2026-10-18/cpu_audit_r15/xm3600_period_cider_decomposition_v1.json :: reference_punctuation_audit.uitviic_test_231.raw_end_period_count ; n_refs ; raw_end_period_rate_pct (raw string count, no segmentation; recounted independently from data/datasets/uitviic/test_data.json, WRITER_B_LOG.md) -->. What appending a period does to CIDEr-D on UIT-ViIC is **PENDING**: it has not yet been measured with the committed scorer.<!-- 2026-10-19 (main, B2 finding 1): the earlier c8 values for UIT-ViIC (94.29% of references ending with a period token after segmentation; +1.29 [0.85, 1.77] CIDEr-D when a period is appended) are withdrawn. c8's UIT-ViIC tokenisation does not reproduce the committed score (24.84 vs 41.71). -->

**Cross-corpus consequence (XM3600).** Unlike KTVIC's, the Vietnamese XM3600 test references are partly punctuated: 217 of the 1,227 end with a period (17.69%)<!-- src: .session_backup/2026-10-18/cpu_audit_r15/xm3600_period_cider_decomposition_v1.json :: reference_punctuation_audit.xm3600_test_600.raw_end_period_count ; n_refs ; raw_end_period_rate_pct (recounted independently from data/datasets/xm3600/test_data.json; WRITER_B_LOG.md) -->. Their CIDEr-D falls from 48.39 to 41.17 and 38.61<!-- src: .session_backup/2026-10-14/r12_verify/xm3600_short_interim_verdict.json :: matcher_v2_tone_normalised|systems|xm3600_zeroshot-short|ngram_scores_scaled_x100|CIDEr ; xm3600_p1_s43-short|... ; xm3600_fuse2_s42-short|... Appending a period to every output of the fine-tuned systems raises their CIDEr-D by +2.71 [2.23, 3.21] for P1 and +2.75 [2.32, 3.20] for fusion. The period is added as a final token after segmentation, the references are unchanged, and the CIs come from a paired bootstrap over images<!-- src: .session_backup/2026-10-18/cpu_audit_r15/xm3600_period_cider_decomposition_v1.json :: cross_system_drop_decompositions_token_level.p1_s43_short_vs_zeroshot_short.drop_decomposition.by_append_period_to_ft_pred.cider_shift_x100.est ; .ci95[0] ; .ci95[1] ; cross_system_drop_decompositions_token_level.fuse2_s42_short_vs_zeroshot_short.drop_decomposition.by_append_period_to_ft_pred.cider_shift_x100.est ; .ci95[0] ; .ci95[1] (meta.bootstrap_draws_B, bootstrap_seed; recomputed independently, WRITER_B_LOG.md) -->. With the period appended, both systems still score below the zero-shot backbone<!-- src: same file :: per_system_cider_configs.xm3600_p1_s43-short.token_level_post_rdr.append_period_to_pred.cider_x100 ; per_system_cider_configs.xm3600_fuse2_s42-short.token_level_post_rdr.append_period_to_pred.cider_x100 ; per_system_cider_configs.xm3600_zeroshot-short.token_level_post_rdr.as_is.cider_x100 (rule: both appended scores < zero-shot as written) -->. The missing period is therefore one measured part of the drop, and we do not decompose the rest. KTVIC fine-tuning transfers KTVIC's unpunctuated template, and even a partly punctuated reference set charges for it. The end-period rates and the period shift are reported here; the XM3600 scores are primary in the companion paper and cited, not re-claimed.

**Recommendation.** Report the punctuation policy with every KTVIC score, and either strip final punctuation from candidates and references or report both numbers.

## 3.4 Segmentation and scorer sensitivity

## 3.5 Object matchers v1, v2 and v3

Object-level scores (CHAIR, object precision and recall) need a matcher that maps Vietnamese words to object classes. We release three versions and state which one each number uses.

- **v1** is the 113-entry Vietnamese lexicon of the FAIR version, applied to raw text.
- **v2** adds tone-mark normalisation: the two placements of the tone mark in syllables such as *hoà/hòa* map to one form. v2 is the primary matcher of this paper. Normalisation changes none of the 2,790 KTVIC test references<!-- src: data/results/tone_norm/SUMMARY.json :: reference_invariance.ktvic_test_2790.m1_changed -->; it changes the matched objects of 30 of 73 scored systems<!-- src: data/results/tone_norm/SUMMARY.json :: meta.ktvic_systems_with_any_change ; meta.ktvic_total_systems -->, because some outputs use the other tone placement.
- **v3** adds rules for classifier nouns, compounds and role nouns. *Cây* is both the noun "tree" and the classifier for long objects (*cây cột* "pole", *cây xăng* "petrol station"), and *cầu* in *cây cầu* is "bridge". Of 980 *cây* tokens the matcher extracts from the training references, 210 are classifier uses and 160 are *cây cầu*<!-- src: .session_backup/2026-10-13/tone_norm/cay_audit.json :: references.ktvic_train_refs.emitted_cay_tokens ; classifier_cay_tokens ; cay_cau_tokens -->. v1 and v2 count all of them as the class "tree". **The v3 rules were drafted by an AI model from training-split counts and have no human sign-off.** We therefore report v3 only as a sensitivity analysis and draw no conclusion that depends on it.

The choice matters for absolute values and little for comparisons. For P1 (seed 42), v3 lowers the number of mentioned classes per caption from 1.823 to 1.706 and raises object F1 from 55.51 to 56.95<!-- src: .session_backup/2026-10-13/r10_cpu/v1_v3_unified_v3_audit_v3.json :: part1_unified_v3_sensitivity.ktvic_test558_systems.p1assist_s42-short.v2.M ; v3.M ; v2.F1 ; v3.F1 -->. The within-writer leave-one-out F1 moves from 60.50 to 61.67<!-- src: .session_backup/2026-10-13/r10_cpu/v1_v3_unified_v3_audit_v3.json :: part1_unified_v3_sensitivity.human_1v4_ktvic_test.v3.macro_by_fold.F1 -->. The frontier exponent used by the ladder (Section 4.3) is 0.7468 under v2 and 0.7470 under v3<!-- src: .session_backup/2026-10-13/r10_cpu/v1_v3_unified_v3_audit_v3.json :: part1_unified_v3_sensitivity.frontiers_ktvic_test.v2.b_anchor_p1_to_fuse2det ; v3.b_anchor_p1_to_fuse2det -->.

On UIT-ViIC, role and child nouns (*đứa trẻ* "child", *đàn ông* "man") dominate the hallucinations counted against COCO classes. A separate role/child canonicalisation, also without human sign-off, lowers CHAIR_i of the KTVIC-trained P1 from 30.02 to 21.39 but of the zero-shot system only from 27.12 to 26.01<!-- src: .session_backup/2026-10-14/r11_verify/c5_n11_uitviic_role_child_audit.json :: uitviic_test.v2.transfer_p1_s43-short.CHAIR_i ; uitviic_test.v3_role_child.transfer_p1_s43-short.CHAIR_i ; uitviic_test.v2.zeroshot-short.CHAIR_i ; uitviic_test.v3_role_child.zeroshot-short.CHAIR_i -->. Under v2 the transferred system has the higher CHAIR_i; under the canonicalisation, the lower. A ranking that flips with an unattested matcher rule is not a finding about the systems. We report it as a reason to publish the matcher with the score. TODO: paired CI for the flip.

## 3.6 Image overlap with other datasets

KTVIC and UIT-OpenViIC draw on a shared image pool and split it independently. 401 of the 558 KTVIC test images (71.86%) match an image in the OpenViIC training split<!-- src: .session_backup/2026-10-13/r10_cpu/r10_a1_a3_spotchecks_v2.json :: A_32_leakage_disclosure.splits.ktvic_test_558.in_openviic_train ; in_openviic_train_pct -->. No model in this paper is trained on OpenViIC: every fine-tuned model was trained on KTVIC train only<!-- src: .session_backup/2026-10-19/HV_LK/b_n2/b_n2_inventory.json ; manuscript/GAP_ANALYSIS_Q1Q2_2026-10-19_ERRATA.md -->. A model trained on OpenViIC must not be evaluated on KTVIC test. The overlap therefore matters for OpenViIC-trained systems, for published and zero-shot comparisons and for the two-panel analysis (Section 5.4), not for our own models' KTVIC scores. A planned leakage test (B-N2), a difference-in-differences between OpenViIC-trained and other systems on overlapping and non-overlapping images, cannot be evaluated, because no OpenViIC-trained run exists. ## 3.7 The release kit and data availability

The audits in this section are the paper's reusable contribution, and we release them as an evaluation kit. Given the datasets from their original sources, each component runs on our committed predictions or on another system's outputs.

**Table 3.1.** Components of the release kit.

| Component | Contents | Used in |
|---|---|---|
| Scorer and protocol card | RDRSegmenter (VnCoreNLP 1.2, jar SHA-256 recorded) applied to candidates and references; BLEU-4, ROUGE-L and CIDEr-D ×100; punctuation variants (as written, final period stripped, period appended) | Sections 3.3, 3.4, 4.2 |
| Object matchers and lexicons | v1 (the lexicon of the FAIR version), v2 (tone-normalised; primary), v3 (classifier, compound and role-noun rules, shipped labelled *unattested*); every object score names the matcher version that produced it | Section 3.5 |
| Splits and ID lists | the dev300 / remaining-training partition of the KTVIC training images; the UIT-ViIC training images that are in COCO Karpathy test, the COCO probe set and POPE-500 | Sections 3.1, 3.6 |
| Two-gold protocol | scores one set of outputs against the dataset's own references and against an independent gold: COCO instance labels for UIT-ViIC, and a second caption panel for KTVIC images (aggregates only); paired image-bootstrap CIs | Sections 5.3, 5.4 |
| Audit scripts | single-writer exchangeability test; within-writer leave-one-out; punctuation and XM3600 period audits; segmentation sensitivity; *cây* audit; image-overlap matcher; frontier residual and the registered ladder check | Sections 3.2–3.6, 5.2 |

**Not released.** We redistribute no images and no reference captions. Readers obtain KTVIC (Pham et al., 2024), UIT-ViIC, XM3600 and COCO from their original sources under their published terms. The fine-tuned checkpoints are available on request until we have confirmed that both the backbone's licence and KTVIC's terms allow derivative weights to be distributed; KTVIC ships no licence file.

For UIT-OpenViIC the rule is stricter: it enters this paper only as aggregate scores. No OpenViIC caption, n-gram or per-image derived file is shown or released. The overlap matcher and the two-gold scripts run on a copy of OpenViIC that the reader obtains from its authors. Every released file is scanned for 8-gram overlap with OpenViIC captions before publication, and the scan must find none.
