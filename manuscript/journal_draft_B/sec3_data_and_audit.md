## 3.2 The five references of an image come from one writer

KTVIC's paper describes an interface in which one annotator types all five captions of an image (Pham et al., 2024, §3.2, Fig. 5). Metrics built on multiple references assume that the references are independent descriptions. We test the assumption directly with an exchangeability statistic on object mentions. Take every object class that exactly two of an image's five references name (a "doubleton"). If the five slots were exchangeable, the two naming references would be adjacent (slots *i* and *i*+1) with probability 4/10 = 0.40.

On the test split the observed adjacent share is 0.7102 [0.6696, 0.7518] over 566 doubletons (z = 15.07 against the null of 0.40)<!-- src: .session_backup/2026-10-14/r11_verify/c3_n2_exchangeability_all_datasets.json :: k5_exchangeability_audit.ktvic_test_objects_in.adjacent_share ; adjacent_share_ci95 ; total_doubletons ; adjacent_share_z_vs_null ; adjacent_share_null -->. The training split shows the same pattern, 0.6673 [0.6499, 0.6852]<!-- src: .session_backup/2026-10-14/r11_verify/c3_n2_exchangeability_all_datasets.json :: k5_exchangeability_audit.ktvic_train_objects_in.adjacent_share ; adjacent_share_ci95 -->, as does dev300, 0.631 [0.5649, 0.6962]<!-- src: .session_backup/2026-10-14/r11_verify/c3_n2_exchangeability_all_datasets.json :: k5_exchangeability_audit.ktvic_dev300_objects_in.adjacent_share ; adjacent_share_ci95 -->. Object-set similarity between consecutive references (lag 1) exceeds the mean similarity at lags 2–4 by 0.135 [0.1178, 0.1538] in Jaccard index<!-- src: .session_backup/2026-10-14/r11_verify/c3_n2_exchangeability_all_datasets.json :: k5_exchangeability_audit.ktvic_test_objects_in.jac_lag1_minus_mean_lag2to4 ; jac_diff_ci95 -->. The pattern is consistent with the single-writer interface: a chain of paraphrases, each written with the previous one in view. A trend over slot positions alone could also raise both statistics, since slot 0 names fewer objects than later slots (Section 4.1). A permutation null that keeps each slot's inclusion rate separates the two explanations (post hoc). Within each image it reassigns which references name which objects, keeping both the number of objects each reference names and the number of references that name each object. Under it the adjacent share averages 0.4504 (95% of 1,000 draws in [0.4134, 0.4876]) and the lag-1 Jaccard excess 0.0355, and no draw reaches the observed 0.7102 or 0.135<!-- src: data/results/b2_controls/slot_null.json :: splits.ktvic_test_objects_in.adjacent_share.null_mean ; .null_ci95 ; .draws_ge_observed (= 0) ; splits.ktvic_test_objects_in.jac_lag1_minus_mean_lag2to4.null_mean ; .draws_ge_observed (= 0) ; draws ; reproduces_audit_k5 (= true) (curveball trades, seed 0; label POST_HOC, CC-088 B-2 a) -->. The training split and dev300 give the same result, with no draw at or above the observed value<!-- src: data/results/b2_controls/slot_null.json :: splits.ktvic_train_objects_in.adjacent_share.draws_ge_observed (= 0) ; splits.ktvic_dev300_objects_in.adjacent_share.draws_ge_observed (= 0) -->. Slot inclusion rates therefore raise the null only a little above 0.40 and do not explain the adjacency. A share above 0.40 is also not by itself specific to a single writer. The statistic is defined in the companion paper, which reports it on other corpora: two caption sets written by independent annotators with a documented protocol, COCO and UIT-ViIC, sit at the null there, while Flickr30k, also written by independent workers, sits above it, which the companion attributes to a non-random file order, and so does the full UIT-OpenViIC test, whose caption-entry protocol is undocumented. The companion in turn leaves the KTVIC case to this paper, so the contrast between KTVIC and the other corpora is split across the two papers, and neither shows it alone. KTVIC's share is well above every value the companion reports, and the KTVIC paper documents the single-writer interface, but the step from the statistic to "one writer" rests on that documentation, not on the statistic alone.<!-- R2 N-M4 (circular controls disclosed, no companion values printed: PD-6) and N-M5 ("at the null on corpora written by independent annotators" was wrong: companion journal_draft/sec5_exchangeability.md Table 5.1 and :33-36 put Flickr30k and OpenViIC full test above the null). --><!-- Figure slot (main, 2026-10-19): place B2's B-only adjacency figure here (.session_backup/2026-10-18/paperA_tasks/B2/fig2_adjacency_Bonly.pdf), never the variant with Paper-A comparators (PD-6). Two consequences follow for evaluation.

- **The references are one writer's view, five times.** A leave-one-out comparison of each reference against the other four gives object P / R / F1 of 85.33 / 46.90 / 60.50<!-- src: data/results/human_parity.json :: 1v4.human.P ; 1v4.human.R ; 1v4.human.F1 -->. Because all five references share one writer, this is a within-writer consistency figure, not a human ceiling; we do not compare systems to it as "human parity".
- **Five references are worth less than five.** The object gold of an image is the union of its references. Under a chain of paraphrases, the extra references add fewer new objects than independent captions would, so recall against the union understates what a caption gets right about the image. Section 5.3 measures this with a second caption panel.

## 3.3 No punctuation in the references, and what one period costs

None of the 2,790 test references and none of the 18,845 training references ends with a period<!-- src: .session_backup/2026-10-14/r11_verify/c1_b1_b6_reproduction.json :: B5_L5_cider_punct_and_uitviic_chair.ktvic_period_audit.test_refs_ending_period ; train_refs_ending_period -->. A system fine-tuned on KTVIC learns this: none of the 558 test outputs of P1-R (seed 42) ends with a period, while 557 of the 558 zero-shot outputs of the same backbone do<!-- src: .session_backup/2026-10-14/r11_verify/c1_b1_b6_reproduction.json :: B5_L5_cider_punct_and_uitviic_chair.ktvic_period_audit.p1assist_s42_short_ending_period ; zeroshot_short_ending_period -->.

**Mechanism.** CIDEr-D weights each n-gram by its inverse document frequency over the reference set and divides the dot product by the norms of the candidate and reference vectors. An n-gram that contains "." has document frequency zero in KTVIC's references. It cannot match, but it still enters the candidate's norm, so every period lowers the score of the whole caption.

**Which pipeline.** The standard COCO scorer, pycocoevalcap, tokenises with the PTB tokenizer and then deletes every token in its punctuation list (".", ",", "?", "!", ":", ";", "-", quotes and brackets) from candidates and references (Chen et al., 2015). Vietnamese pipelines replace that tokenizer with a word segmenter, and with it they drop the punctuation removal. Our committed scorer is such a pipeline (RDRSegmenter, Section 4.2; protocol P0): it scores punctuation as written, and the mechanism above applies to it. The next paragraph gives the sizes under P0; the one after repeats them with PTB-style removal.<!-- CC-088 B-1: pycocoevalcap 1.2 tokenizer/ptbtokenizer.py PUNCTUATIONS = '' ' `` ` -LRB- -RRB- -LCB- -RCB- . ? ! , : - -- ... ; (wheel sha256 083ed791...); rescap/metrics.py sends Vietnamese to _tokenize_vietnamese (segment + lowercase), PTBTokenizer only on the English path -->

## 3.5 Object matchers v1, v2 and v3

Object-level scores (CHAIR, object precision and recall) need a matcher that maps Vietnamese words to object classes. We describe three versions and state which one each number uses; the kit releases v1 and v2.

- **v1** is the 113-entry Vietnamese lexicon of the FAIR version, applied to raw text.
- **v2** adds tone-mark normalisation: the two placements of the tone mark in syllables such as *hoà/hòa* map to one form. v2 is the primary matcher of this paper. Normalisation changes none of the 2,790 KTVIC test references<!-- src: data/results/tone_norm/SUMMARY.json :: reference_invariance.ktvic_test_2790.m1_changed -->; it changes the matched objects of 30 of the 73 KTVIC systems covered by the tone-normalisation rescoring (an inventory compiled separately from the 79 systems of the ranking audit in Section 5.3)<!-- src: data/results/tone_norm/SUMMARY.json :: meta.ktvic_systems_with_any_change ; meta.ktvic_total_systems -->, because some outputs use the other tone placement.
- **v3** adds rules for classifier nouns, compounds and role nouns. *Cây* is both the noun "tree" and the classifier for long objects (*cây cột* "pole", *cây xăng* "petrol station"), and *cầu* in *cây cầu* is "bridge". Of 980 *cây* tokens the matcher extracts from the training references, 210 are classifier uses and 160 are *cây cầu*<!-- src: .session_backup/2026-10-13/tone_norm/cay_audit.json :: references.ktvic_train_refs.emitted_cay_tokens ; classifier_cay_tokens ; cay_cau_tokens -->. v1 and v2 count all of them as the class "tree". **The v3 rules were drafted by an AI model (one of the coding assistants of Section 7.4) from training-split counts and have no human sign-off.** We therefore report v3 only as a sensitivity analysis, draw no conclusion that depends on it, and do not include its rules in the kit.

## 3.7 The evaluation kit and data availability

The audits in this section are the paper's reusable contribution. We release them as an evaluation kit: our own code and documentation, a template for the protocol card, the pre-registration files, score-only copies of the result files the numbers manifest cites (caption fields removed for licensing; each original file's SHA-256 is given) and the manifest itself. Each script runs on the reader's own copy of the datasets and on the reader's system outputs; the XM3600 audit names the paper's six runs, and the reader edits those names to audit other systems.
