The main text reports the dataset-validity audit, the protocol card and the evaluation kit. This supplement holds the complete record of the training and decoding tests run with the controlled system of Section 4. Each verdict is the one its registration or rule produced. None of these results is a contribution of the paper, and none changes its framing. We report them so that no test is left out.

## S1 Registration labels and the extra systems

**Registration labels.** Every test here carries one of four labels, computed from commit, push, file and output times. REGISTERED: the prediction or gate was committed to version control before the first output it covers. LOCALLY_FROZEN: a file with the same SHA-256 was on disk before the first output, but its commit came after that output; we treat such tests as exploratory and give the times. POST_HOC: the registration was written at or after the first output, for example because it quotes the test's own result. EXPLORATORY: no registration covers the analysis. File-system times are supporting evidence, not proof. Two REGISTERED tests, UPE-MBR and the RL gate, were committed before their first output but pushed to the remote only after it<!-- src: .session_backup/2026-10-18/paperA_tasks/A4.4/tests_status.tsv :: tests UPE, RLGATE (t_commit < t_out < t_push) ; rule D-W13-6 (manuscript/WORKFLOW_LOG.md) -->. ## S2 Supervision ladder

### S2.1 Design

The ladder asks whether changing the training *targets*, while keeping backbone, recipe and decoding fixed, moves a system off the precision–count frontier of P1, or only along it. Its predictions were frozen and committed on 2026-10-12 (commit 1b5d16b), before any ladder output existed<!-- src: manuscript/prereg/2026-10-12_ladder_predictions.json -->.

**Frozen anchors.** The frontier is anchored on P1 over three seeds: mean mentioned classes per caption M₁ = 1.7826 (the registered value; Table 5.1's recomputation under matcher v2 gives 1.7825), precision 78.5188, recall 41.8507, and a precision–count exponent b = 0.7468<!-- src: manuscript/prereg/2026-10-12_ladder_predictions.json :: anchors.frontier.M1 ; P1 ; R1 ; b -->. A run's *frontier residual* is its observed precision minus the precision the frontier predicts at its count. Where a table reports a residual on F1, it is object F1 minus the frontier's F1 prediction at the same count, and the table says so. The count-matched frontier is the companion paper's method; here it is used as a tool.

**Targets.** The recipes change the number of objects per training target: P1's targets carry 1.618 objects per row and cons's 2.033<!-- src: manuscript/prereg/2026-10-12_ladder_predictions.json :: training_targets.p1-short.objects_per_row ; training_targets.cons-short.objects_per_row -->. The implied reference-support thresholds are 0.505 and 0.352<!-- src: manuscript/prereg/2026-10-12_ladder_predictions.json :: training_targets.p1-short.tau ; training_targets.cons-short.tau -->.

**Two models.** Under *L*, a fine-tuned model's count follows the length of its targets and its precision follows one learner frontier. Changing targets then moves a run along the frontier, and residuals are zero. Under *T*, an ideal learner thresholds each object's reference support at the target's implicit threshold. Counts then follow the thresholds and can fall below the target length. The registration gives, for each run, intervals for M, precision and recall, and *L* vs *T* discriminators.

**Registered H0 (frontier invariance).** H0 is a conjunction. Each run's point frontier residual must lie within ±1.0, and the mean residual over all landed runs must have a 95% CI that contains 0, with its point in [−0.8, +0.8]<!-- src: manuscript/prereg/2026-10-12_frontier_invariance_V4.txt:233-236 (commit 1b5d16b; per-run clause l.235, pooled clause l.236) ; pooled part also in manuscript/prereg/2026-10-12_ladder_predictions.json :: structural.joint_frontier_invariance -->. The registration notes that a single run's residual CI is about ±2 points at 558 images, so single-run claims cannot be resolved, while the pooled residual can<!-- src: manuscript/prereg/2026-10-12_frontier_invariance_V4.txt:241-242 -->.
