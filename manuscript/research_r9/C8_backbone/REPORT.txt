0. BOTTOM LINE

1. ">= 90" is NOT reachable through this lever on any of the four targets, and the backbone is not what limits them.
   KTVIC (gold = union of the 5 KTVIC references):
   - The SFT systems' "false" objects are real objects.
     - Against the independent OpenViIC panel, the real fraction of P1-short's reference-false mentions is
       97.3 % [85.6, 109.6]; fuse2-detailed 95.7 % [87.6, 104.6] (data/results/second_panel.json).
     - So even a PERFECT perceiver adds at most P +0.5 [0, +2.9] (P1-short) or +1.1 [0, +3.1] (fuse2-detailed).
   - Recall is lost to mention policy, not vision: 81.6 % of P1-short's misses are named by >= 2 of the 70 other
     outputs of the SAME backbone (69.9 % by >= 5).
   - Perception injection is already measured: Grounding-DINO tags in the prompt move fuse2 KTVIC F1 by only
     +0.3 [-1.0, +1.6] (short) and +0.4 [-0.9, +1.7] (detailed).
   - Human ceilings on the same metric: one caption 85.3 / 46.9 / 60.5; two fused 76.1 / 66.6 / 70.9.
   COCO (gold = instances only, 2,500 probe images):
   - An ORACLE that names exactly the instance classes some of the 5 COCO annotators named, and nothing else, scores
     P 100 / R 74.3 / F1 85.3.
   - The union of the 5 human captions scores 85.3 / 74.3 / 79.5 [78.7, 80.2]; one human caption 92.6 / 56.6 / 70.3.
   - F1 >= 90 needs R >= 81.8 even at P = 100, i.e. naming objects that NO human mentioned. That is an object
     inventory, which is metric gaming.
2. R6-B5 ("about 0 CIDEr from a backbone swap") re-evaluated for OBJECT metrics:
   - It carries over to KTVIC object P/R/F1: expected F1 +0 to +1 (central +0.3).
   - It only PARTLY carries over to COCO F1, where some real perception and naming errors remain after SFT:
     - 14.8 % of the human-salient instance classes are never named by any of 8 Qwen2.5-VL-7B outputs. Examples:
       kites described as "cờ bay ... hình cá" / "lồng đèn", a fire hydrant as "van nước màu đỏ", a surfboard as
       "thuyền paddleboard".
     - 5.5-7.6 % of SFT mentions are named by neither the instances nor any reference.
   - Expected effect of a stronger backbone: COCO F1 +1 to +3 after SFT, and +1 to +4 zero-shot detailed (projection,
     section 4c).
   - CIDEr 0 to +2 (B5), so there is no caption-quality cost and nothing is gamed.
3. Literature agrees, and the gains are a few points in FREE-FORM description (numbers in section 4a):
   - Same protocol, Qwen3-VL 2B -> 8B -> 32B: CHAIR_i 13.2 -> 11.2 -> 10.9; caption recall 72.1 -> 75.4 -> 76.5
     (VISE, ECCV 2026).
   - Object HalBench CHAIR_i: Qwen2.5-VL-7B 7.7 -> InternVL3-8B 6.5 -> MiniCPM-V 4.5 5.2.
   - POPE: 86.4 -> 88.7-91.1.
4. Proposals: C8-A Qwen3-VL-8B (primary) and C8-B InternVL3.5-8B (alternate).
   - Both go through ONE pre-registered zero-shot object-truth screen: 2.5 GPU-h per backbone, inference only.
   - Then a 1-seed dev-split gate against the existing p1dev_s42 (4.2 GPU-h), then 3 fuse2 seeds (about 21 GPU-h).
   - Novelty: none (engineering). The value is diagnostic:
     - The paper can state that object metrics are reference- and policy-bound, not backbone-bound.
     - It gains an Apache-2.0 8B second backbone in place of the "qwen-research"-licensed Qwen2.5-VL-3B.

=====================================================================================================================
4. RE-EVALUATION OF B5: does a stronger backbone raise object P and R even if CIDEr stays flat?
=====================================================================================================================
(a) Zero-shot, free-form description: YES, by a few points. Each comparison below is within one table.
    - Qwen3-VL 2B -> 4B -> 8B -> 32B (VISE, ECCV 2026, Table 3):
      - COCO CHAIR_i 13.2 -> 12.9 -> 11.2 -> 10.9;
      - caption object recall 72.1 -> 74.9 -> 75.4 -> 76.5;
      - POPE 88.4 -> 88.5 -> 88.6 -> 89.5.
    - Object HalBench CHAIR_i (MiniCPM-V 4.5 report, Table 1): Qwen2.5-VL-7B 7.7 -> InternVL3-8B 6.5 -> MiniCPM-V 4.5
      5.2 (thinking mode).
      - Qwen2.5-VL-72B scores 8.9, so a bigger model does NOT always hallucinate less: it writes more.
    - AMBER (SAVAA, Table 3): LLaVA-NeXT-7B 7.83 / 63.87 -> Qwen3-VL-8B 7.66 / 73.59 -> InternVL3.5-8B 7.49 / 74.24.
      Coverage +10, CHAIR flat.
    - POPE (InternVL3.5 report, Table 6): Qwen2.5-VL-7B 86.4 -> InternVL3.5-8B 88.7 -> InternVL3-8B 91.1.
    - Our zero-shot detailed output does hallucinate: 57 % real fraction on KTVIC and 16 % absent mentions on COCO.
      Zero-shot is where a better backbone has room.
(b) After KTVIC SFT, scored against KTVIC gold: NO measurable room (P2, P3).
    - Perfect perception would add P <= +0.5 [0, +2.9] (P1-short) or +1.1 [0, +3.1] (fuse2-detailed).
    - A realistic backbone that removes 16-32 % of hallucinations realises only about +0.1 to +0.3 of that.
    - Recall: 70-82 % of misses are seen by the same backbone; the remainder is mostly wording.
    - Expected: KTVIC P +0 to +0.5, R +0 to +1, F1 +0 to +1 (central +0.3), consistent with the measured G-DINO-tag
      effect. B5's "about 0 CIDEr" therefore carries over to the object metrics.
(c) After KTVIC SFT, on COCO transfer: SMALL room (P1). PROJECTION, not a measurement.
    Inputs:
    - Hallucination reduction r_h in [8, 32] % of the absent pool. Basis: CHAIR_i -16 % for InternVL3-8B and -32 % for
      MiniCPM-V 4.5 vs Qwen2.5-VL-7B; the lower end allows for half the pool being table/chair class-definition errors.
    - Recovery r_f in [8, 30] % of the never-named salient misses. Basis: same-protocol recall gains close 12 % (VISE
      2B -> 8B) to 27 % (AMBER, LLaVA-NeXT -> Qwen3-VL-8B) of the miss pool.
    Projected results:
    - fuse2-detailed: P 88.9 -> 89.4-91.1, R 52.3 -> 53.2-55.5, F1 65.8 -> 66.7-69.0 (central 67.4, +1.6).
    - fuse2-short: F1 59.4 -> 60.3-62.7 (central 61.1).
    - Zero-shot detailed: F1 73.4 -> 74.4-77.1 (central 75.3).
    - Zero-shot short: F1 63.3 -> 64.1-66.3 (central 64.8, +1.5). That central value sits exactly on S0's short-mode
      pass bar, so S0 is a fair test, not a formality.
    - Arithmetic: P' = P / (1 - absent share x r_h); R' = R + r_f x (R_fix - R); both from P1's table.
    - The recall lost to KTVIC style (zero-shot detailed 67.5 vs fuse2-detailed 52.3) is a style effect. It reappears
      with ANY backbone fine-tuned on the same targets.
(d) CIDEr and BLEU: 0 to +2 CIDEr, B-4 within +-1 (B5: PaliGemma 1 -> 2 changed COCO CIDEr by -0.6 and COCO-35L by
    -1.9; LM size 3B -> 10B added +1.4 to +2.4; fine-tuned Gemma 3 4B / 12B / 27B scored 143 / 143 / 144).
    - No caption-quality cost, and no metric gaming: the captions stay the same length and style.

5. PROPOSALS (novelty: none; engineering with pre-registered gates; ranked by information per GPU-h)
=====================================================================================================================
SHARED GATE S0: zero-shot object-truth screen. Inference only. Pre-register before any output.
  Runs:
  - Code: coco_probe.py and pope_vi.py, with only the model loader swapped.
  - Settings: bf16, greedy, 60 / 160 new tokens, the evaluate.PROMPTS Vietnamese prompts, 256-1,024 vision tokens
    (InternVL: <= 4 tiles + thumbnail).
  - Data:
    - COCO probe short on all 2,500 images;
    - COCO probe detailed on a fixed 1,000-image subset: random.Random(0).sample(sorted(cocoid), 1000);
    - POPE-vi, Vietnamese only, 5,127 questions.
  Comparison:
  - Against the EXISTING Qwen2.5-VL-7B zero-shot outputs on the same images (no rerun).
  - Scoring: object_prf.py COCO block (instances-only gold, matcher v2) plus pilot_coco_ceilings.py (absent share and
    never-named share); paired image bootstrap, B = 5000.
  Guards:
  - Report the share of captions that are Vietnamese and the CJK leakage rate.
  - Report the same deltas on the probe images that lie in COCO val2017: about 300 of the 2,500 expected, not counted
    here.
    - train2017 = train2014 + val2014 - val2017, so about 88 % of Karpathy-test images are expected to be in COCO-2017
      train, which the newer backbones' grounding data (COCO, Objects365) likely covers.
    - If a pass vanishes on the val2017 subset (CI includes 0 and the point estimate is below half the full-set point),
      call it contamination-driven.
  GPU-h on one 3090: about 2.5 per backbone (5.0 for both).
  - Short: 0.85. Detailed (1,000 images): 1.25. POPE-vi: 0.35.
  - Basis: measured 4090 latency of 0.86 s (short) and 2.06 s (detailed) per image, x1.4 for a 3090; zero-shot detailed
    output runs to the 160-token cap.
  PASS (per backbone):
  - COCO detailed dF1 >= +2.0 with CI lower bound > 0, OR COCO short dF1 >= +1.5 with CI lower bound > 0;
  - AND the absent share does not rise;
  - AND mentions per caption stay within +-15 % of Qwen2.5-VL-7B. Otherwise judge on the absent and never-named shares
    only, and call the F1 change style-confounded.
  KILL the lever if no backbone passes. Then keep Qwen2.5-VL-7B and use the better candidate only as the
  second-backbone replication (C8-B's fallback).

GATE G1 (S0 winner only). Dev split, P1 recipe, 1 seed. The comparator already exists: n2 runs/p1dev_s42 (Qwen2.5-VL-7B,
  gold_p1dev = train minus dev300).
  - Train the winner on the same rows with p1dev_s42's mask, LR and epochs.
  - Score both adapters: KTVIC dev300 object P/R/F1 and CIDEr (short), plus the COCO probe short (2,500 images).
  - GPU-h: train about 2.2 (1.15 x 1.92 h) + eval 2 x (0.15 + 0.85) = about 4.2.
  - PASS:
    - COCO short dF1 >= +1.5 with CI lower bound > 0;
    - AND dev300 object F1 drops by no more than 1.5 (point estimate);
    - AND dev300 CIDEr drops by no more than 3;
    - AND peak memory <= 22 GB and step time <= 1.6x Qwen2.5-VL-7B's.
  - Otherwise KILL.
STAGE 3 (only after G1 passes): fuse2 with the assistant mask, 3 seeds, full train.
  - Test on KTVIC test and on the COCO probe (short 2,500, detailed 1,000).
  - GPU-h: about 3 x (4.4 + 0.5 + 2.1) = about 21.
  - Claim only paired deltas whose pooled CI excludes 0.
  - Report CIDEr, B-4 and METEOR next to every object number.

C8-A  Qwen/Qwen3-VL-8B-Instruct (PRIMARY)
  Mechanism: same QLoRA recipe on the newer Qwen generation.
  - SigLIP2 vision tower + DeepStack, 32 px per token: about 20 % more pixels at fewer tokens (B5).
  - Same BPE tokenizer as now, so Vietnamese tokenisation is unchanged.
  - Smallest port: AutoModelForImageTextToText, transformers >= 4.57.
  Evidence: POPE 88.6; COCO CHAIR_i 11.2 and caption recall 75.4 (VISE); AMBER CHAIR 7.5-7.7 / Cover 73.6-73.7;
    HallusionBench 61.1 vs 52.9; CountBench 89.8 vs 86.4.
  Closest prior: VISE arXiv 2606.27373 (backbone comparison, English CHAIR); B5; PaliGemma 2 arXiv 2412.03555 and
    Gemma 3 arXiv 2503.19786 (Table 12) for fine-tuned captioning.
  Expected:
  - S0: COCO short F1 63.3 -> 64.1-66.3; detailed 73.4 -> 74.4-77.1; RePOPE-vi 87.3 -> 88-90.
  - After SFT (fuse2):
    - COCO detailed 65.8 -> 66.7-69.0; short 59.4 -> 60.3-62.7.
    - KTVIC short F1 58.1 -> 58.1-59.1; detailed 64.4 -> 64.4-65.4.
  - CIDEr 0 to +2.
  GPU-h: 2.5 (S0) + 4.2 (G1) + 21 (stage 3). The lever stops at 2.5 if S0 kills it.
  Kill: S0 / G1 rules above. Engineering kills: peak > 22 GB at a 512 cap, or step time > 1.6x.
C8-B  OpenGVLab/InternVL3_5-8B-HF (ALTERNATE; screen it in S0 only if C8-A fails or produces poor Vietnamese)
  Evidence:
  - POPE 88.7. AMBER 7.49 / 74.24, the best Cover of the 8B models compared.
  - RefCOCO 89.7. MTVQA 35.2 (text VQA in 9 languages, Vietnamese included), the best 8B in its table.
  - Weaker: HallusionBench 54.5 vs 61.1, CountBench 75.6.
  Risks:
  - 448-px square tiles distort 3:2 photos unless >= 2 tiles are used.
  - A different chat template and processor mean a larger port.
  Expected: same ranges as C8-A, with slightly more precision and slightly less counting.
  GPU-h and kill: as C8-A.
  Fallback value if both fail S0: use the better of the two as the Apache-2.0 second backbone (3 P1 seeds, about
  10 GPU-h). Its expected object delta vs Qwen2.5-VL-7B is 0 +- 1.5 F1, and that null result is itself the paper's
  robustness evidence.
Not proposed:
- Qwen3.5-9B: strongest card, but needs transformers 5.x, uses Gated-DeltaNet layers and 15-17 GB. Add it to S0 only if
  the 5.x environment exists.
- MiniCPM-V 4.5: best Object HalBench score, but only in thinking mode, and remote code.
- Ovis2.5-9B: best RefCOCO and HallusionBench 65.1, but remote code and no POPE/CHAIR numbers.
- Gemma-3-12B: gated, the lowest POPE of the group, 256 squashed tokens.
- Vintern: 0.5-3B LMs, plus the unverified leakage risk.
- LLaVA-OV-1.5/2: no hallucination numbers.

Can this lever reach >= 90?  NO, on every target.
- KTVIC P: best case about 79-82 (P1-short 78.8 + 0.5 [0, 2.9]). Human 85.3.
- KTVIC R: about 43-44 short, about 62-63 detailed. Human 46.9 (1 caption) / 66.6 (2 fused). Recall is bounded by the
  number of objects a caption names.
- KTVIC F1: about 56 short, about 65-66 detailed. Human 60.5 / 70.9.
- COCO F1: about 67-69 after SFT, about 74-77 zero-shot.
Deciding numbers:
- KTVIC: the 97.3 % [85.6, 109.6] real fraction of P1's false mentions, and 81.6 % of its misses named by the same
  backbone elsewhere.
- COCO: the salient-only oracle reaches F1 85.3 (R 74.3), so >= 90 needs objects no human named.

=====================================================================================================================
7. SIDE FINDINGS (outside this lever; found while measuring)
=====================================================================================================================
- KTVIC lexicon orthography:
  - objects_in("một tòa nhà") gives ['nhà'], while objects_in("một toà nhà") gives ['toà nhà'].
  - KTVIC test references write "toà nhà" 82 times and never "tòa nhà". The SFT systems learned "toà"; zero-shot
    detailed writes "tòa" 67 times.
  - This penalises every zero-shot or new-backbone comparison on KTVIC. Normalise tone-mark placement (òa/oà, óa/oá,
    ủy/uỷ, ...) in canonical() before matching, or screen backbones on COCO only (as S0 does).
- COCO-probe contamination: about 88 % of the Karpathy test images are expected to be in COCO-2017 train
  (train2017 = train2014 + val2014 - val2017; the overlap was not counted here). The candidates' grounding data covers
  COCO (Qwen3-VL: COCO, Objects365, OpenImages, RefCOCO). Hence S0's val2017 check.
- Vintern / OpenViVQA image overlap with KTVIC test: unverified (2J). Check it before any use.
- CJK leakage (Qwen2.5-VL-7B Vietnamese captions):
  - zero-shot detailed 5.2 %;
  - COCO after KTVIC SFT 0.6-2.2 %;
  - KTVIC after SFT 0-0.2 %.
  When a leaked token replaces an object word, the matcher misses it.
