LENS 1 - NOVELTY  (incremental; not scooped as an exact combination, no element is a step beyond prior art)
=====================================================================================================================
Searches (2022-2026 focus): arXiv API 21 queries (several returned empty: syntax/throttling; re-run with simple
terms), Semantic Scholar 2 and OpenAlex 4 (HTTP 429 on every attempt, as B1/B7 saw; no e-mail or ID parameter sent),
WebSearch 8. Topics: captions of similar images as extra reward references; neighbour/kNN pseudo-references in SCST
and semi-supervised captioning; reference-set expansion with paraphrases/retrieval under a CIDEr reward; empirical-Bayes
/ James-Stein shrinkage in RL rewards and baselines; hallucination / object penalties in caption RL (SCST, GRPO, LVLM);
GRPO + CIDEr captioning; retrieval-augmented rewards in LLM RL; Vietnamese captioning + RL; Re3Cap.
Closest prior, element by element (abstracts read for all ids below):
 - Neighbour references in the reward: CIDErBtw, Wang et al. ECCV 2020 (2007.06877; journal 2204.03938) builds the same
   similar-image reference sets and uses them in the RL reward with the opposite sign (R = CIDEr - 0.4 CIDErBtw).
   Flipping the sign is the only change in this element. No paper found with lam > 0 (query "captioning neighbors
   references reward" -> 0 hits). Related: Zheng et al. 1808.09564 (pseudo-references built from the SAME example's
   refs; +11.7 CIDEr in captioning), Chaffin et al. 2402.13936 (GT captions added to the RL reward pool), CST (Phan
   et al. 2017, consensus of GT captions as baseline), RefAlign 2504.09895 (similarity to reference answers as reward).
 - Empirical-Bayes shrinkage: 2511.03710 (James-Stein shrinkage baselines for RLVR), EBPO 2602.05165 (empirical-Bayes
   shrinkage of GRPO baselines toward global statistics), PEBS 2606.27578 (Morris-James-Stein shrinkage of per-rater
   reward calibration toward the population). Shrinking a reward TARGET is a small step from these, and in practice it
   is decorative: the proposal's primary lam is 0.5 picked on dev, not the EB value 0.80 (and see lens 3: the EB value is
   the worst-performing one).
 - Reference-gold object penalty (the CHAIR term): SC-Captioner, ICCV 2025 (2508.06125): RL reward matches the caption's
   object/attribute/relation sets against REFERENCE sets with "mistake punishments for wrong additions"; CIDEnt
   (1708.02300) corrects CIDEr against contradicted content; MOCHa (2312.03631); FoCUS (2609.00709: negative weights
   for out-of-scope objects in GRPO); CCCaption (2602.21655: hallucination penalty); CHAIR-DPO (2508.20181); VES-RFT
   (CVPR 2026). The "metric-matched gold" twist is an ablation detail, not a new mechanism.
 - Re3Cap (2608.21305): retrieval as prompt guidance (CRS/CQA), rewards SC/CLIP/CIM; does not score against retrieved
   refs. No 2024-2026 RL or LVLM KTVIC/UIT-ViIC CIDEr paper found (arXiv "Vietnamese captioning": datasets only).
Novelty verdict: an incremental reward recipe (sign-flipped CIDErBtw + a prior-art hallucination penalty + EB framing).

LENS 2 - FEASIBILITY ON ONE RTX 3090  (feasible per run; budget ~2x the claim; three implementation risks)
=====================================================================================================================
- Memory: unchanged from CN-RLOO (reward is CPU). n2 measurement: the G0 sampler alone (P1_dev, k=8) holds 21.5 GB of
  the 24.6 GB 3090 (nvidia-smi compute-apps). Training at k=8 adds the ref forward and backward, so the B1-P1 fixes
  (bf16 cast of non-quantised params, or k=4) are likely needed. Inherited risk, not PB-specific.
- Throughput measured on n2: G0 sampling ~10-11.5 s per image (dev300: 300 images in ~49-57 min; train300: 120 images in
  ~24 min), 2-3x B1's 3-4.5 s estimate. With the update (~1.3 s) about 12 s/image, so a G1 arm (1,000 images + 4-5 dev
  evals) is ~4 h, and the 2-arm gate is ~8 h (claimed 5).
- GPU-h for the claim the proposal makes: gate 8 + matched-KL tuning ~4 + KTVIC 3 seeds x ~12.5 h (3,469 images) = 38
  (+25 for 5 seeds if a between-seed +8 claim is made) + UIT-ViIC 3 x (SFT ~1.5 + RL ~9-10 h on 2,695 images) ~ 33
  (claimed 6) -> ~80-110 GPU-h (claimed 41). CN-RLOO's own seeds are still needed as the comparison arm.
- Implementation risks:
  (a) DEV LEAKAGE: HEAD rl_reward.Reward loads every train reference set. If the neighbour pool is all of train, 57.4% of
      RL-pool images (train - dev300) get >= 1 dev300 image among their 10 neighbours (mean 0.81; 285/300 dev images
      reached), so the PB arm is rewarded on dev references and the gate is biased in its favour. The proposal does not
      exclude dev300 from the neighbour index.
  (b) "Matched KL" is not a knob in train_rl.py (fixed k3 KL coefficient, no std normalisation of RLOO advantages).
      Reward SD across the 8 rollouts: NCR 0.86x plain, PB 1.13-1.39x (dev, 4 splits), so at equal lr/beta the arms
      move different distances. Matching needs per-arm tuning or checkpoint matching, which means more GPU-h and more
      forking paths.
  (c) The copy-neutral mask looks only at OWN refs and misses the cross-image copy channel that NCR strengthens (lens 3).

=====================================================================================================================
WHY KILL (not modify)
=====================================================================================================================
1. The only new element (NCR with an EB weight) gives ~0 to +1.5 on the actual init once the judge's own sentences are
   removed from the reward (half the headline is leakage; the control rules out neighbourhood quality), tends to 0 as
   own refs grow toward the RL setting (5), lowers the independent panel, and strengthens unmasked template copying.
2. What remains (the CHAIR term) is prior art (SC-Captioner, CIDEnt, MOCHa, FoCUS, CCCaption). It lowers CHAIR partly
   by fewer and vaguer nouns, and on P1 it costs CIDEr (-1.2 [-1.8, -0.5] alone on test samples).
3. The expected increment is below single-seed MDE (2.5-3.8) and below the dev300 SE (3.0-4.8). The gate as written
   cannot falsify the method.
Salvage (zero novelty claim, optional, ~4 GPU-h): if B1 runs G1, add one arm "CN-RLOO + beta 0.25 x #nouns outside the
own-ref CHAIR gold (lam = 0)", cite SC-Captioner/CIDEnt/MOCHa, report dev CHAIR_i, the OpenViIC-gold CHAIR_i,
nouns/caption and the specific-vs-generic noun share, and keep it only if CHAIR_i falls >= 1.5 at dCIDEr >= -1 and the
specific-noun share does not fall > 10%.
If anyone runs PB anyway: neighbour index = train - dev300; copy mask over own + neighbour refs; sanitized-proxy
prediction (+0 to +1.5 CIDEr) pre-registered; NCR kept only if NCR-only - CN-RLOO >= +3.0 with paired LB > 0 on
the LAST checkpoint; 80-110 GPU-h.
