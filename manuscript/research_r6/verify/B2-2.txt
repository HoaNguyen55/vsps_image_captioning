VERDICT: KILL.
  Novelty: incremental. Every part has prior art: learned rewriting from same-image caption pairs, a fine-tuned LLM
           that fuses a caption set, synthetic captions to close a target benchmark's style gap, language pivoting,
           and tagged synthetic data. The only delta is the instance: two same-language human panels on overlapping
           images. On UIT-ViIC the "pivot panel" is English COCO, which is plain language pivoting (Gu 2018, Lan 2017).
  Gain:    the mechanism evidence (4x images = +22..+26 stand-in points) is a retrieval-proximity property of the
           kNN stand-in under every decoder. It says nothing about a pretrained 7B VLM. Synthetic-target precedents
           at baselines >= 128 CIDEr give +0 to +2, and the in-repo precedent (E5) gave -8. Realistic: 0 +- 3 CIDEr over
           MR5, inside seed noise.
  Gates:   the gate-2 rule (+1.5 dev CIDEr, one run per arm) passes a NULL effect 39% of the time.
  Cost:    the real budget is ~120-225 GPU-h, not 59. It also spends the OpenViIC independent panel, and the
           UIT-ViIC arm as written leaks all 231 UIT-ViIC test images.

2. LENS 3, GAIN REALISM
-----------------------------------------------------------------------------------------------------------
2a. The design contradicts its own mechanism. The gain is supposed to come from "more images carrying the KTVIC
    style", yet bridged rows carry a tag that is absent at test.
    - Tagged: the untagged (test) mode is trained only on MR5 rows, and bridged rows act only through shared visual
      learning. The proposer concedes the stand-in cannot see that channel, and the closest prompt-tagged
      multi-dataset captioner gains +0.2 CIDEr (Wang et al. AAAI 2023, arXiv:2212.01803, per B2's reading).
    - Untagged: the bridge LM's modal phrasing enters the test mode. That is E5's failure mode (rejection-sampling FT
      on model text: 137.9, about -8 vs P1).
    - The tagged back-translation analogy is inverted. BT has synthetic SOURCES and real targets. PanelBridge has real
      inputs and synthetic TARGETS, i.e. forward translation / sequence-level KD. There a <SYN> tag vs no tag was not
      significant (arXiv:2006.02876), and forward translation gains less on target-original text and risks
      translationese (Bogoychev & Sennrich, arXiv:1911.03362).
2b. Literature effect sizes at strong baselines (all far larger data than 8.6k images):
    - BLIP CapFilt, synthetic captions + filter for 14M/129M pretraining images, COCO fine-tuned CIDEr: 127.8 -> 129.7
      and 130.1 -> 131.4, i.e. +1.9 / +1.3 (arXiv:2201.12086 Table 1, HTML read).
    - CapsFusion (arXiv:2310.20550 Table 1, HTML read): +5 to +19 CIDEr, but in a 10-100M-image pretraining regime with
      a frozen LLM at 97-116 CIDEr, not a fine-tuned 146 model.
    - PaliGemma (arXiv:2407.07726 Sec. 6.3, HTML read): "The majority of the tasks can reach within 10% of the
      full-data score when using 4 k examples" (full COCOcap 141.9). So 28x more REAL in-style data is worth at most
      ~10%. 2.3x more SYNTHETIC rows should be worth a small fraction of that.
2c. In-repo precedent: synthetic targets in SFT lowered CIDEr (E5 137.9; E5+DPO 123.1). PanelBridge's content is
    human-attested, but its wording is LM-generated modal text, the property that hurt E5.
2d. Seed noise and the gates (gate_noise.py). Same-recipe P1 runs (4 legacy seeds), all ordered pairs, 296 of the
    558 test images resampled to mimic the dev split (B=2000 per pair group): SD of a one-run-per-arm dev difference
    = 5.3 CIDEr (image sampling alone: per-image SD 59.9 -> 3.5).
      P(gate 2 "diff >= +1.5" passes): true effect 0 -> 0.39; +1.5 -> 0.50; +3 -> 0.60; +5 -> 0.73; +8 -> 0.88.
      A 5% false-pass dev gate needs diff >= +8.6.
    So gate 2 cannot separate the claimed +0..+5 from noise. The test claim needs >= 5-6 seeds per arm or a paired
    bootstrap pooled across seeds (CONTEXT: 3 seeds detect about +12.7).
2e. Stacking with MR5. B2-1 found MR5's own realistic gain is about 0 (-3..+3) once the stand-in uses greedy-type
    decoders. The proposal's "+4 to +12 stacked (30%)" therefore needs PanelBridge alone to reach about +8: P < 5%.
2f. Metric gaming. No length or repetition lever: bridged targets would match KTVIC length. The risk is template
    concentration: P1 already opens 95.9% of captions with "co", and P1 copies a train caption verbatim in 20-23% of
    test outputs (B2-1). Modal bridged targets would push both up. Report copy rate, distinct-n and the opening share.
=> Realistic: CIDEr 0 +- 3 over MR5 (point 0 to +1); B-4 / METEOR / ROUGE-L within +-1; CHAIR_i within +-1.5
   (human-attested content could lower it slightly, unproven). P(P1 mean + 8) < 5%.

3. LENS 1, NOVELTY: INCREMENTAL (no exact match found; every element is prior art)
-----------------------------------------------------------------------------------------------------------
Closest prior, and what each already does:
- LaCLIP, Fan et al. NeurIPS 2023, arXiv:2305.20088 (HTML read, Sec. 3.2 + App. C.1). Its "MSCOCO" strategy takes
  two human captions of the SAME image as source -> target rewrite pairs, then rewrites the captions of OTHER images
  (CC3M/CC12M/RedCaps/LAION) with LLaMA-7B to make new training text. PanelBridge = the same recipe, with the pair
  taken across two panels, a fine-tuned rewriter and a target-benchmark style.
- CapsFusion, Yu et al. CVPR 2024, arXiv:2310.20550 (HTML read, Sec. 3). A fine-tuned LLaMA-2-13B (trained on 1M
  ChatGPT fusion triplets) fuses a caption SET (raw alt-text + BLIP caption) into one caption for 120M images. This is
  the "fuse a set of captions into one target caption" element. FuseCap (arXiv:2305.17718) and IC3
  (arXiv:2302.01328) fuse caption sets with an LLM too.
- NICE 2024 solution, arXiv:2404.12739 (abstract + search summary). Closes a new human test set's caption-STYLE gap
  by re-annotating extra training images with captioners kept in the target (COCO) style. Same purpose as
  PanelBridge, but the content comes from captioners.
- MoCHA, arXiv:2603.23684 (2026, abstract). A learned caption canonicalizer (GPT-5.2 and a distilled FlanT5) removes
  annotator-specific style across two datasets and improves cross-dataset transfer. Same idea of a learned
  text-to-text style mapping between datasets' annotator styles (motion-text retrieval).
- Language pivoting (Gu et al. ECCV 2018, arXiv:1803.05526), fluency-guided translated captions (Lan et al. MM 2017,
  arXiv:1708.04390), pseudopairs across disjoint caption datasets (Kadar et al. 2019, arXiv:1911.03678). The
  UIT-ViIC arm (English COCO -> Vietnamese) IS this line, so the replication would test prior art, not PanelBridge.
- Teacher pseudo-captions for unlabeled images (arXiv:2201.02010); BLIP CapFilt (arXiv:2201.12086).
- Tag component: tagged BT (arXiv:1906.06442), tagged forward translation (arXiv:2006.02876), prefix conditioning
  (arXiv:2206.01125), prompt-tagged multi-dataset captioning (arXiv:2212.01803). Pseudo-style self-learning across
  caption datasets: "Cross-domain multi-style merge for image captioning", CVIU 228 (2023) (abstract).
Remaining delta: the source caption set is a second same-language HUMAN panel, and the fuser is supervised by the
target benchmark's human captions on the overlapping images. This is a dataset-specific instance of learned caption
rewriting/fusion, not a new mechanism and not a "breakthrough".
Searches:
- arXiv API, 16 queries (2022-2026 filters where useful): caption style transfer + pseudo; caption fusion / CapsFusion /
  LLM fuse captions; rewrite captions + "another dataset"; language pivot captioning; semi-supervised captioning +
  pseudo; Vietnamese image captioning; annotation style + caption; LLM rewrite + style; cross-dataset captioning style;
  pseudo captions + unlabeled images; language rewrites / MSCOCO in-context; dense captions + summarize; stylized
  captioning + pseudo; "caption style"; multi-dataset prompt style; text-only + target style.
- OpenAlex + Semantic Scholar, 4 queries: HTTP 429 from this IP (as for B2 and B2-1).
- WebSearch, 11 queries: two-dataset style mapping + pseudo-labels; LLM rewrite to benchmark style; Vietnamese
  captioning 2025-26 (no KTVIC/OpenViIC captioning paper beyond the dataset papers; ViCLIP-OT is retrieval);
  prefix/dataset tags with the tag removed at test; cross-domain multi-style merge; semi-supervised captioning at
  strong baselines; sDCI LLM summaries of human dense captions; PaliGemma limited-data transfer; caption
  harmonization; Kadar 2019 pseudopairs; tagged forward translation.
- Full text read in this session: LaCLIP, CapsFusion, PaliGemma, BLIP (HTML).

4. LENS 2, FEASIBILITY on one RTX 3090 (24 GB), Qwen2.5-VL-7B 4-bit QLoRA, scripts/train_stage2.py @HEAD
-----------------------------------------------------------------------------------------------------------
- Memory: fits. Bridged rows are image + prompt(+tag) + ~12-word caption, the same shape as P1 rows (512 vision
  tokens at 4-bit, batch 1 x 8). The text-only bridge is lighter.
- Implementation, moderate-low risk, 3 code changes:
  (i)   a text-only bridge trainer and generator. VLCollator/to_chat always attach an image, so a new ~150-line
        script is needed.
  (ii)  image_for() reads only DATA/datasets/$NCS_DATASET/images, so a mixed KTVIC+OpenViIC row set needs a
        per-row image root or a symlink dir. No name collisions: every KTVIC file name's same-name OpenViIC copy is
        matched and so excluded from FREE.
  (iii) tag rows, the SSCD drop list (46 files), and OpenViIC images on the training node.
- GPU-h, at the measured 0.91 s per row-epoch (n2) and 2 epochs:
    bridge LoRA text-only (17,140 rows)       ~3 h      (proposal 1.5)
    bridge labelling (dev + 8,596 FREE)       ~1 h
    MR5-dev comparator                        8.8 h     (not in the 59)
    MR5+bridge dev run (25,941 rows)          13.1 h
    non-synthetic control dev run             13.1 h    (1 row/image; ~29 h with all captions; not in the 59)
    bridge retrain on full train + relabel    ~4 h
    test seed (27,441 rows) + eval            14.5 h/seed: 3 seeds 43.5 h, 5 seeds 72.5 h
    MR5 test seeds to compare against         10 h/seed (only if B2-1's MR5 is not run)
    UIT-ViIC arm (bridge + label + 3 seeds + MR5 baselines) ~60 h
  Totals: ~117 GPU-h for a 3-seed KTVIC-only version; ~225 GPU-h for a powered (5 seeds/arm) version with the
  required replication. The proposal's 59 GPU-h covers neither. Every single run fits one 3090 (<= 14.5 h).
- Other costs:
  - It spends the OpenViIC independent panel. Bridged content comes from OpenViIC annotators, so second-panel
    precision stops being independent. CONTEXT requires a no-OpenViIC variant for every second-panel analysis; the
    proposal does not state this.
  - FREE contains 1,365 OpenViIC TEST and 1,102 OpenViIC DEV images, so no OpenViIC benchmark number could be
    reported afterwards.
  - Bridged targets are derived from licence-restricted OpenViIC text and must stay git-excluded.
  - Synthetic training data is a user veto point.
