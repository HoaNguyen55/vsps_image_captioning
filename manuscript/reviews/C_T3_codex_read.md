# C-T3 launch review — commit `deee879`

**Launch readiness: 38/100 — BLOCK.** Static review only; no test images were extracted or decoded.

1. **[BLOCKING] The stated one-sided bootstrap “p” is not a calibrated null p-value.** `p_one_sided` resamples the observed differences without centering at the null and counts bootstrap means ≤ 0 ([c_t3.py](/mnt/d/vsps_image_captioning/scripts/c_t3/c_t3.py:1153)). This estimates a bootstrap tail probability around the observed mean, not the sampling probability under Δ ≤ 0. The +1 correction does not fix that. Holm’s step-down implementation itself is correct ([c_t3.py](/mnt/d/vsps_image_captioning/scripts/c_t3/c_t3.py:1159)), but applying it to these quantities does not support the registered significance claim. Resolve the inferential method before launch and amend the preregistration.
2. **[BLOCKING] LMCap can overwrite its test predictions on a second direct invocation.** `cmd_lmcap` allows the registered `ri` test run ([c_t3.py](/mnt/d/vsps_image_captioning/scripts/c_t3/c_t3.py:453)) but writes the final prediction and checksum without checking whether either exists ([c_t3.py](/mnt/d/vsps_image_captioning/scripts/c_t3/c_t3.py:523)). Unlike `cmd_decode`, it has no write-once guard. This bypasses the single-look promise even though the shell job normally skips a `.done` arm.
3. **[BLOCKING] Scoring is repeatable and can write test-derived rows into any chosen file.** `score` accepts any `--ledger` path and opens it in append mode ([c_t3.py](/mnt/d/vsps_image_captioning/scripts/c_t3/c_t3.py:796), [c_t3.py](/mnt/d/vsps_image_captioning/scripts/c_t3/c_t3.py:864)); it neither refuses an existing ledger nor restricts test ledgers to the preregistered external location. Repeating it appends duplicate rows, while choosing a development ledger path puts test IDs/scores in dev artifacts. This conflicts with the one-call scoring plan and the no-test-leak commitment ([PREREG.md](/mnt/d/vsps_image_captioning/manuscript/prereg/2026-10-31_c_t3/PREREG.md:165), [PREREG.md](/mnt/d/vsps_image_captioning/manuscript/prereg/2026-10-31_c_t3/PREREG.md:299)).
4. **[BLOCKING] Ledger run IDs are not bound to the scored configuration.** Scoring checks dataset/schema and smoke suffix, but does not validate `run_id` against model, arm, k/order/template, memory, or predictions ([c_t3.py](/mnt/d/vsps_image_captioning/scripts/c_t3/c_t3.py:798)). `t3` checks only that each test `run_id` is in the seven-name allow-list, then `set_columns` builds contrasts from the separately supplied model/arm fields ([c_t3.py](/mnt/d/vsps_image_captioning/scripts/c_t3/c_t3.py:1203), [c_t3.py](/mnt/d/vsps_image_captioning/scripts/c_t3/c_t3.py:1033)). A mislabeled or altered ledger can therefore assign an authorized ID to a different arm/configuration and still enter the decision.
5. **[NON-BLOCKING] Near-duplicate preflight reuse is not validated.** The job skips the pre-decode pass whenever any nonempty `neardup.json` already exists ([c_t3_job.sh](/mnt/d/vsps_image_captioning/scripts/c_t3/c_t3_job.sh:59)); it does not validate that file’s label/schema or its recorded manifest hashes before decoding. A stale or substituted file can bypass the promised fresh preflight. The normal clean run does compute the pass before V0/GPU decode.
6. **[NON-BLOCKING] Preregistration status is stale.** It says “Not committed” although this review targets the commit that contains it ([PREREG.md](/mnt/d/vsps_image_captioning/manuscript/prereg/2026-10-31_c_t3/PREREG.md:3)).

## Re-read after fixes

**Launch readiness: 89/100 — BLOCK pending small corrections.** Static review only; no test images were extracted or decoded.

1. **#1, method description needs qualification.** Keeping the registered method is appropriate: the test statistic remains the preregistered uncentred bootstrap tail with +1, and `t3_decide` uses that p and Holm, not the printed CI. Calling it CI inversion is broadly descriptive, but “p ≤ α exactly when” is not exact for this implementation: `contrast` uses NumPy’s interpolated percentile while `p_one_sided` uses a +1 corrected discrete count. At α=.05 those can disagree at the boundary. The reported +24.63 to +34.81 val effects and lower bounds above +20 make this distinction immaterial to the already-fixed tier-2 family; they do not guarantee the unseen test decision. A test result near its threshold could differ if someone substituted CI exclusion for the registered p rule. Disclose the tail quantity as the registered bootstrap p-like statistic, not an exact null p-value or exact CI inversion.
2. **#2–#4 addressed in the normal workflow.** LMCap now checks the predictions and checksum paths before loading models. Test scoring refuses an existing/wrongly named/in-repo ledger or a directory with another JSONL, validates each frozen run configuration and adjacent prediction checksum before importing scorers or reading references, and writes the required config/hash fields. `t3` cross-checks those fields against the run sums before decision output. This removes the reviewed overwrite, arbitrary score-ledger, and run-id/config substitution routes.
3. **#5 partly addressed; residual integrity gap, non-blocking for the primary decision.** Restart checking matches label, rule, pinned input identifiers, and staged manifest hashes, but accepts any `sets`/`exclude`/`parity`/`truncated` payload once those fields match. An edited exclusion list can therefore be reused and misstate the beside-only dedup result; the all-image decision is unaffected. Validate the payload against a stored output hash or recompute it before treating reuse as verified.
4. **#6 addressed.** Preregistration now identifies the committed baseline and amendment.

**Disposition:** The main original blockers #2–#4 are closed. The stated launch bar is ≥92; score remains below it for the exactness overclaim in #1 and the reusable near-duplicate payload gap in #5. No new issue found in the reviewed decode, score, decision, or job-restart paths beyond those listed above.
