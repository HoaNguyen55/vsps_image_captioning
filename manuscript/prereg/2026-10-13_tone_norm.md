## 1. Tone-Mark Normalisation Rule and Touched Lexicon Entries

Vietnamese orthography has two conventions for placing tone marks on open syllable-final vowel clusters `oa`, `oe`, and
`uy`:
- **Old style** (tone mark on the medial vowel): `òa óa ỏa õa ọa òe óe ỏe õe ọe ùy úy ủy ũy ụy` (e.g. `tòa nhà`, `tàu hỏa`, `tàu thủy`).
- **New style** (tone mark on the main vowel): `oà oá oả oã oạ oè oé oẻ oẽ oẹ uỳ uý uỷ uỹ uỵ` (e.g. `toà nhà`, `tàu hoả`, `tàu thuỷ`).
- **Closed syllables** (with a final consonant or semivowel, e.g. `hoàng`, `thoại`, `buýt`, `đoàn`, `quý`) place the tone
  mark on the main vowel in both styles and are identical.

Across both matcher lexicons (`rescap/vi/lexicon.py` and `data/coco_probe/coco80_vi.json`), 9 entries contain a
syllable-final open `oa`/`oe`/`uy` cluster: 5 are written in new style and 4 in old style. New style is therefore the
canonical target (matching `scripts/nap.py:65` `_TONE`).

### 1.1 Implementation (`rescap/chair.py` and `scripts/score_coco_probe.py`)

```python
_TONE = dict(zip("òa óa ỏa õa ọa òe óe ỏe õe ọe ùy úy ủy ũy ụy".split(),
                 "oà oá oả oã oạ oè oé oẻ oẽ oẹ uỳ uý uỷ uỹ uỵ".split()))
_TONE_RE = re.compile("(" + "|".join(_TONE) + r")(?![^\W\d_])")


def norm_tone(text: str, *, raw_tone: bool = False) -> str:
    s = unicodedata.normalize("NFC", text)
    if raw_tone or os.environ.get("RESCAP_RAW_TONE") == "1":
        return s
    return _TONE_RE.sub(lambda m: _TONE[m.group(1)], s)
```

1. **Matcher M1 (`rescap.chair.objects_in`)**:
   - `_NOUNS = {norm_tone(k): k for k in NOUN_CLASSIFIER}` maps every tone-normalised lexicon key to its lexicon string.
   - `_COLOUR_PHRASES` passes each phrase through `norm_tone`.
   - `objects_in(text, *, raw_tone=False)` normalises the lowercased input via `norm_tone(text.lower())` before stripping
     colour phrases and matching 3-, 2-, 1-token candidates against `_NOUNS - _NOT_OBJECTS`.
   - Both reference captions (`_gold_objects`) and model captions (`chair`, `object_prf`, etc.) call `objects_in`, so
     gold and predictions are normalised identically.
2. **Matcher M2 (`scripts/score_coco_probe.vi_objects` / `vi_classes` / `load_vi_terms`)**:
   - `load_vi_terms(*, raw_tone=False)` normalises every term from `data/coco_probe/coco80_vi.json` via
     `norm_tone(t.lower(), raw_tone=raw_tone)`.
   - `vi_classes(caption, vi_terms, *, raw_tone=False)` normalises the lowercased caption via
     `" " + norm_tone(caption.lower(), raw_tone=raw_tone) + " "`.

## 2. Verbatim Self-Check Assertions

### 2.1 `rescap/chair.py:_check` (executed via `python3 -m rescap.chair`)

```python
def _check() -> None:
    import doctest
    import sys

    r = doctest.testmod(sys.modules[__name__])
    assert r.failed == 0 and r.attempted >= 6, r
    assert objects_in("một tòa nhà") == objects_in("một toà nhà") == ["toà nhà"]
    assert objects_in("một tòa nhà cao") == objects_in("một toà nhà cao") == ["toà nhà"]
    assert objects_in("một tòa nhà cao", raw_tone=True) == ["nhà"]
    assert len(_NOUNS) == len(NOUN_CLASSIFIER)
    inv = {v: u for u, v in _TONE.items()}
    old_re = re.compile("(" + "|".join(inv) + r")(?![^\W\d_])")
    clusters = [k for k in NOUN_CLASSIFIER if old_re.search(k) or _TONE_RE.search(k)]
    assert clusters == ["toà nhà"], clusters
    for k in clusters:
        old_k = old_re.sub(lambda m: inv[m.group(1)], k)
        new_k = norm_tone(k)
        assert old_k != new_k and objects_in(old_k) == objects_in(new_k) == [k], (k, old_k, new_k)
    for w in ("hoàng", "thoại", "buýt", "quý"):
        assert norm_tone(w) == w
    assert norm_tone(unicodedata.normalize("NFD", "tòa nhà, khỏe, thủy")) == "toà nhà, khoẻ, thuỷ"
    assert objects_in(unicodedata.normalize("NFD", "một tòa nhà cao")) == ["toà nhà"]
```

## 5. CJK-Rate Column and Sensitivity-Row Protocol (Judge D10 (iv)(b))

1. **Regex definition**:
   - `scripts/cjk_rate.py` and `scripts/abs_halluc.py` both use `scripts/clean_supervision.py:CJK_RE`:
     `re.compile(r"[⺀-〿぀-ヿ㐀-鿿가-힯豈-﫿＀-￯]")`.
   - On all 73 KTVIC prediction files, `CJK_RE` is identical to the full Unicode CJK block union (including CJK
     Extension A/B, Kana, Hangul, CJK symbols/punctuation, and halfwidth/fullwidth forms).
2. **Output (`data/results/cjk_rate.json`)**:
   - Stores `{n_captions, cjk_captions, cjk_pct, cjk_ids}` for all 73 KTVIC `.preds.json` files, 6 UIT-ViIC `.preds.json`
     files, 3 Group-A `.json` files, and 9 COCO shard `.jsonl` groups (`coco5000`, `coco5000_vcd`, `coco_transfer`).
   - Never writes caption text.
   - Measured KTVIC summary:
     - `p1assist_s42/43/44` (short & detailed), `p1_s43` (short & detailed), `p1-gold` (short & detailed),
       `mr5assist_s42` (short & detailed), `p1mask_s42` (short & detailed): **0.0%** (0 / 558).
     - `fuse2_s42` short / detailed: **0.0%** (0 / 558) / **0.2%** (1 / 558); `fuse2_s43`: **0.9% / 0.9%** (5 / 558);
       `fuse2_s44`: **0.9% / 0.7%** (5 / 558, 4 / 558).
     - `zeroshot` short / detailed: **0.7%** (4 / 558) / **5.2%** (29 / 558).
     - Older pipelines: `vcd-detailed` **17.0%** (95 / 558), `official-detailed` **27.8%** (155 / 558),
       `roundA-detailed` **41.8%** (233 / 558 `CJK_RE`; 231 Han-only + 1 Hangul + 1 CJK period `'。'`).
3. **Sensitivity-row rule**:
   - A system's CJK-free sensitivity score is computed by the **same evaluation script** on the subset of images where
     its own caption has no `CJK_RE` match (`image_id not in cjk_ids`).
   - Paired deltas between two systems in a sensitivity row use the intersection of their CJK-free image sets (images
     where neither caption contains CJK; `object_prf._vs_table` already intersects image IDs).
   - Never present a CJK-suppressed re-decode as an existing baseline.
