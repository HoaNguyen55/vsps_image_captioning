## 1. The method and frozen constants (`scripts/plan_f1.py`)

PLAN-F1 separates *which objects to name* (content selection for the corpus evaluation metric) from *how to write the
sentence* (one-sentence realisation):

1. **Calibrated union-of-describers posterior (`plan_f1.py` lines 109-175).**
   - For each image, the candidate object pool is the union of `rescap.chair.objects_in` (the 113-entry Vietnamese
     lexicon, exact class match) over `P1_dev`'s greedy short caption and 12 stochastic samples (`N_PER_T = 6` at
     `T = 0.5` and `6` at `T = 0.8`, `TEMPS = ("0.5", "0.8")`).
   - For each pooled class `o`, the feature vector is `x = [1, v, g, v*g, lp, v*lp]`, where:
     - `v` is the fraction of the 12 samples naming `o`;
     - `g in {0.0, 1.0}` indicates whether the greedy caption names `o`;
     - `lp = log(p_o / (1 - p_o))` is the logit of the Laplace-smoothed class prior `p_o = (c_o + 0.5) / (3469 + 1)`
       (unseen class prior `0.5 / 3470`), where `c_o` is the number of KTVIC `train_minus_dev300` images (3,469 images)
       whose 5-reference union names `o`.
   - The target `y in {0, 1}` is whether `o` is in the union of the image's 5 KTVIC references.
   - The calibrator is an L2-penalised logistic regression (`L2 = 1e-2` on the 5 non-intercept weights, intercept
     unpenalised, solved by Newton's method for up to `NEWTON = 50` steps with stopping tolerance `1e-9`), together
     with the mean number of gold classes outside the pool per image, `lam = mean(|G \ pool|)`.
   - **Dev (`--split dev`):** 5-fold cross-fitting (`FOLDS = 5`, `FOLD_SEED = 0`: `random.Random(0).shuffle` of the
     `int`-sorted 300 dev image IDs, `rank % 5`, 60 images per fold). Each fold's `q` and `lam` are predicted from the
     weights and `lam` fitted on the other 4 folds.
   - **Test (`--split test`):** one weight vector `w` and scalar `lam` fitted on all 300 dev images (`dev300`):
     `w = [-0.546491452313066, 2.820271901198645, 0.09830254316744204, -0.35461502179001664, 0.28093674120425005, -0.30845290684180454]`,
     `lam = 1.2266666666666666` (1,307 dev pooled items, positive rate `0.523336`). No test reference is read.

2. **Metric-Bayes decision rule (`plan_f1.py` lines 187-230).**
   - `object_prf.py` defines corpus micro precision `P = sum |M_i & G_i| / sum |M_i|`, macro recall
     `R = mean_i(|M_i & G_i| / |G_i|)`, and `F1 = 2 P R / (P + R)`.
   - Linearising `F1` around the corpus operating point `(P*, R*, m)` (where `m` is mean classes per image) gives the
     inclusion rule:
     $$\text{include } o \text{ in image } i \iff q_{i,o} + \kappa \, w_{i,o} \ge P^*, \qquad \kappa = \frac{(P^*)^2 m}{(R^*)^2}$$
     where $w_{i,o} = \mathbb{E}[y_{i,o} / |G_i|] = q_{i,o} \, \mathbb{E}[(1 + \sum_{o' \ne o} y_{i,o'} + Z_i)^{-1}]$
     is computed by exact Poisson-binomial convolution over $o' \ne o$ (`Bernoulli(q_{i,o'})`) convolved with
     `Z_i ~ Poisson(lam_i)` truncated at `POIS_MAX = 30`.
   - `(P*, R*, m)` is iterated to a label-free fixed point under `q` starting from `START = (0.75, 0.45)` and
     `m_0 = greedy_classes_per_caption` for up to `FP_STEPS = 100` steps: at each step, `inc = (q + kappa * w >= P)`,
     then `P = q[inc].sum() / max(inc.sum(), 1)`, `R = w[inc].sum() / N`, `m = inc.sum() / N`.
   - **Cap and ordering:** at most `CAP = 3` included classes per image are kept, ordered by `q` descending (ties
     broken by class name ascending). A 3-class cap keeps the plan inside the KTVIC single-sentence reference
     distribution (leave-one-out human reference CIDEr-D is 192.2 at 3 classes vs 160.2 at 4+ classes; `REPORT.txt`
     section 3f).

3. **List-conditioned SFT realiser (`plan_f1.py` lines 60-93).**
   - Base training rows: `scripts/build_gold_sft.py` on KTVIC `train_data.json` filtered to
     `data/splits/ktvic_train_minus_dev300.txt` (3,469 images, first caption in file order, `PROMPTS["short"]`, seed
     42; sha256 `971879742e85d710fc828fa526b735d0c0b6469b4988e3d5402a26fb1b666f16`, identical to `P1_dev`).
   - `plan_f1.py realiser-data` extracts each target caption's own object list in first-mention order deduplicated,
     `plan_of(response) = list(dict.fromkeys(objects_in(response)))`, and appends the exact `evaluate.py --tags` suffix
     when non-empty:
     `prompt + " Các đối tượng có thể có trong ảnh: " + ", ".join(plan) + "."`
     It asserts on every row that `plan_in(prompt) == plan_of(response)` and `set(plan_in(prompt)) == set(objects_in(response))`.
   - Training recipe (`51_planf1_dev.sh`): identical to `P1_dev` (`35_a`):
     `python scripts/train_stage2.py --stage sft --data $NCS_DATA/gold_planf1 --out $NCS_DATA/runs/planf1_s42 --epochs 2 --seed 42 --loss-mask assistant`
     (backbone `Qwen/Qwen2.5-VL-7B-Instruct`, 4-bit NF4, 512 vision tokens, batch 1 x grad_accum 8, lr `1e-4`, LoRA
     `r = 16`, `alpha = 32`, `dropout = 0.05` on language-tower projections only, response-only loss mask).
   - Realisation decode: `scripts/evaluate.py` (unmodified, sha256 `a68d5682...`) with `--prompt short --tags PLAN.json`,
     greedy decoding (`do_sample=False`, `max_new_tokens=160`, `max_vision_tokens=512`, bf16).

Under D10's binding condition, any realised gain must therefore be reported strictly as a *metric-derived operating-point shift inside one sentence*, never as better object ranking.

## 4. Kill criteria K1-K3 (verbatim) and conditional test rule

Verbatim from `REPORT.txt`, section 5 (lines 338-343):

```
  Kill (pre-register before any decode; all on dev300 with the train-minus-dev300 control adapter):
    K1 fidelity: realised captions name < 85% of the planned classes, or add > 0.3 unplanned classes per caption;
    K2 realised KTVIC dev object F1 gain over greedy < +3.0 or its CI includes 0, or gain over UPE-frozen < +1.0.
       (Plan level on dev T0.8 x6, cap 3: +3.7 over greedy and +2.1 over UPE; 12-20 samples add about 1-2.)
    K3 KTVIC dev CIDEr-D < greedy - 5, or BLEU-4 < greedy - 3.
    Test runs once, everything frozen. Report negative if test dF1 < +2 or CIDEr < greedy - 8.
```

Operational reading in `scripts/plan_f1.py score`:
- **K1 (`res["K1"]`):** across the 300 dev images, let $P_i = \text{set}(\text{plan}_i)$ and
  $M_i = \text{objects\_in}(\text{realised}_i)$.
  - `named_share = sum(|P_i & M_i|) / max(sum(|P_i|), 1) >= 0.85` (`K1_NAMED`);
  - `unplanned_per_caption = sum(|M_i - P_i|) / 300 <= 0.3` (`K1_UNPLANNED`);
  - `K1.pass = (named_share >= 0.85) and (unplanned_per_caption <= 0.3)`;
  - `K1.by_plan_size`: per-plan-size (`|P_i| in {0, 1, 2, 3}`) breakdown of `n_images`, `named_share`,
    `unplanned_per_caption`, and `exact_match_share`, isolating the train-to-dev plan-size distribution shift (`16.4%`
    of realiser training rows have `>= 3` classes vs `70.3%` of `dev300` plans at `|P_i| = 3`).
- **K2 (`res["K2"]`):** paired dev object F1 differences (`object_prf.paired`, `n = 5000`, seed 0):
  - `vs_greedy["F1"][0] >= 3.0` (`K2_GREEDY`) and 95% CI lower bound `vs_greedy["F1"][1] > 0`;
  - `vs_upe["F1"][0] >= 1.0` (`K2_UPE`, where UPE is the frozen D9 rule at `T* = 0.5`);
  - `K2.pass` holds iff all three inequalities hold.
- **K3 (`res["K3"]`):** on dev300:
  - `d_cider_d = boot(cider_realised - cider_greedy)[0] >= -5.0` (`-K3_CIDER`);
  - `d_bleu4 = eval_BLEU4(realised) - eval_BLEU4(greedy) >= -3.0` (`-K3_BLEU4`);
  - `K3.pass` holds iff both inequalities hold.
- **Dev verdict (`res["verdict"]`):** `"PASS"` iff `K1.pass and K2.pass and K3.pass`, else `"KILL"`.
  - If `verdict == "KILL"`, the pilot stops here; no test decode is run, and the dev numbers are reported as a
    negative result.

### Conditional test step (only if dev `verdict == "PASS"`)
