## Order and temperature (D1f)

1. 36_z_dev_samples (D9 step A, prepared by another agent) runs before any RL look. D9's step-A pre-registration, with
   its temperature reading, is committed before 36_z runs.
2. The reading is **positive** when the R0 pick's dev panel CIDEr-D gain at T = 0.8 has a paired 95% CI above 0.
   - If it is positive, the first look is `35_e_rl_cn_t08first_v3.sh` (T = 0.8), and T = 1.0 is the clean-kill
     fallback.
   - Otherwise, the first look is `35_e_rl_cn_v3.sh` (T = 1.0), and T = 0.8 is the clean-kill fallback.
3. Exactly one first-look file is queued, and only after the reading exists. The queue runs jobs in name order, and
   `36_z` sorts after `35_*`, so the two must not be queued together.
4. Either first-look job stops before any GPU command once a first look exists (`rl/g1_cn_v3_s42` or
   `rl/g1_cn_t08_v3_s42`). 35_f and 35_g find the first look by those directories and stop unless exactly one exists.
5. The two first-look files differ only in the line `T=1.0; TAG=` / `T=0.8; TAG=_t08`. At both temperatures the gate,
   the guards and the two-look rule are identical. Only the copy-rate baseline differs (guard G4).
6. 35_f runs every follow-up at the first look's temperature. 35_g runs the fallback at the other temperature.

## The first look

The job stops before any GPU command unless the dev split verifies (C1) and P1_dev's dev CIDEr-D is at least 120 (the
D1b floor). The CN-RLOO arm starts from P1_dev:

| setting | value |
|---|---|
| images | the first 1,000 of the seed-42 order of train minus dev300 |
| samples | k = 8 at temperature T (top_p 1, top_k 0, no repetition penalty), max 40 new tokens |
| log-probs | logits divided by T in the sampler and in both the policy's and the reference's log-probs |
| update | 5 images per optimizer step, AdamW lr 2e-5, one inner epoch (the ratio clip 0.2 is inert) |
| KL | k3 KL to P1_dev, beta 0.03 |
| reward | word-level CIDEr-D (RDRSegmenter, sigma 6) with an end token on references and finished rollouts. The df comes from the references of all 3,769 train images, dev300's included, so that the C3 replica check against pycocoevalcap is exact. Dev images are never RL images. |
| copy mask | m(c) >= 0.90: advantage 0, outside the leave-one-out baseline |
| fragment guard | END = words that end at least one train-minus-dev reference. A rollout whose last word is not in END keeps its place in the baseline, but its advantage becomes min(A, 0). |
| seed and memory | seed 42; --micro 4, last-position logits, expandable_segments, LoRA dropout 0 |

A fresh 20-image dry run (k = 8, at the arm's temperature) comes first and stops the job unless every check holds:
- log-prob gap below 0.02 nat/token;
- sampler equal to the policy;
- reward replica within 1e-6 of pycocoevalcap;
- loss mask covering generated tokens only;
- peak reserved memory at most 22 GB.

The in-run dev evaluations (4-bit, every 250 images) are monitoring only. No checkpoint is selected, and only OUT/last
is ever gated. No job here decodes or scores the KTVIC test set.

## Gate v2

Delta is the paired difference, over the 300 dev images, between the per-image word-level CIDEr-D of the run's last
checkpoint and P1_dev's. Both are decoded by evaluate.py (bf16, greedy). rl_report.py recomputes the per-image scores
and asserts that they reproduce evaluate.py's corpus score to 1e-6. Its mean equals dev CIDEr-D minus 144.334.

The 95% interval is a percentile bootstrap: B = 2000 resamples of images, numpy default_rng(0).

Guards (all must hold; measured on the evaluate.py dev captions unless stated):

| guard | threshold |
|---|---|
| G1. Captions ending in a function word | <= 1% |
| G2. Fragment captions (END as above) | <= P1_dev's count + round(0.02 n), as integer counts: <= 9 + 6 = 15 of 300 |
| G3. Mean syllables | >= 0.9 x P1_dev's, i.e. >= 10.69 |
| G4. Exact-copy rate of the rollouts in the last 250-image block | <= 2 x step 0 |

G4's step 0 depends on the temperature:
- At T = 1.0 it is G0's train rate of 0.67%, floored at one copy, so the limit is 1.33%.
- At T = 0.8 it is the arm's own first 250 images, because G0 sampled at T = 1.0. This is lenient, since the first block
  already includes 50 RL steps (D1f (e)).

Mentions per caption, CHAIR_i and the OpenViIC panel are reported for every gated run. None of them gates anything.

The final KL is the mean KL per caption over the last 250-image block.

Verdict, decided in this order:
1. **pass**: delta >= +3.0, the 95% lower bound > 0, and every guard holds.
2. **under-moved**: not pass, every guard holds, and the final KL < 0.2 nat.
3. **grey**: every guard holds, and either +1.0 <= delta < +3.0, or delta >= +3.0 with the lower bound <= 0.
4. **kill**: anything else. A guard failure is a kill at any KL.

A kill is **clean** when the run moved (final KL >= 0.2) and every guard held.

Look 2 (only after the grey extension): pass by the same rule, otherwise kill. D1e registers the two-look rule as it is.
A lower bound above 0 is required at each look, so an arm with no true effect passes with probability about 5%.

Rulings on the threshold choices (D1f):
- **G2:** amended from "+1.0 point" to +2.0 points, compared as counts. An absolute 1% would fail P1_dev itself (3.0%).
- **Grey requires every guard** (accepted). A guard failure is a kill.
- **Under-moved before grey** (accepted, amended). Under-moved also requires every guard.
- **Mentions are not gated** (accepted). Length (G3) is the content-dropping guard. R6_00's draft of this gate also
  required mentions >= 0.9 x P1_dev's (1.58).
- **T = 0.8 copy baseline** = the arm's own first 250 images (accepted, lenient as stated above).

D1f's amended rules, verbatim (decisions/D1f.txt):

## Follow-ups

Follow-ups are pre-registered as well. They run at the first look's temperature unless stated. 35_f and 35_g read the
verdict and refuse to run on a missing or unknown one.

- **pass** (look 1): the plain-RLOO arm (--no-copy-mask), 1,000 images, judged by gate v2. Then CN vs plain on the same
  dev images.
  - The copy mask is claimed only if CN - plain >= +3.0 with a paired 95% lower bound > 0.
  - Otherwise CN-RLOO is reported as an engineering recipe (RLOO + end token + fragment guard), and the mask as a
    one-seed ablation.
  - B1-P1 adds two conditions for a paper claim. The first is a G0 share of at least 10%: it holds on the RL images
    (11.1%) but not on dev (9.9%). The second is a full-scale test win over plain RLOO, pooled over at least 3 seeds,
    with a lower bound > 0.
- **grey:** the one extension of the first look to all 3,469 train-minus-dev images, judged at look 2.
  - The extension uses `--resume`: the policy and its AdamW state come from OUT/last, and the KL anchor stays P1_dev.
  - It trains on the remaining 2,469 images of the same seed-42 order, so no image is reused.
  - Only a look-2 pass is followed by the plain arm and CN vs plain at 1,000 images, as after a look-1 pass. After a
    look-2 kill there is no plain arm (D1f).
  - The full-scale stage uses N* = 3,469 images after a look-2 pass, and N* = 1,000 after a look-1 pass (R6_00 §5d).
- **under-moved:** exactly one CN rerun at lr 5e-5 (first-look settings otherwise), judged as a first look.
- **clean kill** (of the first look, or of its lr 5e-5 rerun): one fallback CN arm at the other temperature, not the
  plain arm.
  - It uses the first look's settings otherwise, a fresh dry run at its temperature, and gate v2.
- **Anything else** has no pre-registered next step. This includes a kill that is not clean, a pass after the lr 5e-5
  rerun, and any verdict of the fallback arm.
  - A further RL run needs a new judge decision.
  - Without one, the paper's system is R6_00's row (b): C-MBR over SFT adapters, without RL.

GPU budget per branch (D1f): about 3.5 GPU-h for the first look. Then:

| outcome | follow-up | GPU-h |
|---|---|---|
| pass | plain arm | about 3.5 |
| under-moved | lr 5e-5 rerun | about 3.5 |
| grey, then look-2 kill | extension | about 6.9 |
| grey, then look-2 pass | extension and plain arm | about 10.4 |
| clean kill | fallback temperature | about 3.5 |
| kill that is not clean | none | 0 |

## Predictions (made before any G1 output; estimates, not results)

Source: verifier B1-P1. Its effect-size estimates are for the KTVIC short test against a seed- and mask-matched P1,
from a transfer bound over four reference splits computed on test samples; nothing was tuned on them. They were made for
T = 1.0 rollouts and are applied here to the dev pilot. No separate prediction is registered for T = 0.8.

| metric | predicted change |
|---|---|
| CIDEr-D | +2 to +6, central about +4 |
| B-4 | +1 to +3 |
| ROUGE-L | +0.5 to +2 |
| METEOR | -0.5 to +1 |
| CHAIR_i | -1 to +2 |

- P(gain >= +8 with CHAIR_i not worse) is about 10-15%.
- CN vs plain RLOO: within +-2 CIDEr-D, so the copy mask is not expected to be claimable.
  - In G0, rollouts at tau take about as much of the positive advantage on unseen dev images (9.9%) as on the SFT'd
    train images (11.1%).
  - So the mask mostly removes the naturally best samples, not memorised ones (D1e).
- No prediction that CHAIR falls.
  - In Rohrbach et al. 2018 (arXiv 1809.02156, Table 1), self-critical training raised CHAIR_i for four of five
    captioners (TopDown 6.1 -> 8.8).
  - KTVIC CHAIR is derived from the references, so a drop there would show typicality, not truth.
