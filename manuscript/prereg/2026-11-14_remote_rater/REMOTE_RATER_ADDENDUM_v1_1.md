**What changes.** Only how R2 reaches the page. The PI's own sessions stay in person. Nothing in the pinned rating code, pages or assignments changes:
- `tools/obj_rater/pair_server.py` da36692d, `pair.html` 1dde2ecf, `server.py` e3beb936, `rater.html` 84a90787 stay byte-identical and keep binding 127.0.0.1 (page test E8 still holds for the servers). Through the gate and the tunnel, however, R2's page becomes reachable from the internet by whoever holds the session key, which the in-person default excluded.
- New element 1: a token gate `gate_proxy.py` v1.1 (this folder; sha256 353bb6e7cd5314fd2a9d769222e5e460a36b1258d427265796abde6ec8b22535; v1 was 6a1c07b4…) listening on 127.0.0.1:8890. It forwards only to the ONE running rater page (8792 for Paper B, 8793 for Paper A; any other target is refused at start). It lets a request through only with an HttpOnly, Secure, SameSite=Lax cookie that is set once from a link carrying a random 48-hex key; that link redirects to the practice page (`/?practice`). It forwards GET and POST /save (body of 8 KB at most) and logs method, path class (/, image, /assignment.json, /practice.json, /state/assignment, /state/practice, /save, other) and status only: never a body, a key, a label or an address.
- New element 2: a Cloudflare quick tunnel, `cloudflared` 2026.11.0 (GitHub release binary, sha256 51f7c68b57ed7269164075d7e789efce5b59355982f06392deeb037d982a51fd, kept in the home folder, no account), started as `cloudflared tunnel --no-autoupdate --url http://127.0.0.1:8890`, so that the binary cannot replace itself during a session. It gives a random https://…trycloudflare.com address, which is written in no LOG line and no repo file.

**Session procedure (each remote session).**
1. Before the rating server starts: `ss -ltnH` shows nothing on 8790–8793 or 8890; no `cloudflared` and no `gate_proxy` process runs; every earlier rating session has its session-end line (Paper B also needs its GATE-SERVE line). The server is started for R2 only: Paper A `server.py --dir ~/vsps_labels/xm600_gold_r2 --annotator R2 --port 8793`; Paper B `pair_server.py --dir ~/vsps_labels_b/b_pref --annotator R2 --images data/datasets/ktvic/images` (port 8792).
2. A NEW key per session (`secrets.token_hex(24)`, file mode 600, never shown, printed or logged) and a new gate log file per session; then the gate (byte-equal to the committed gate_proxy.py v1.1) with `--target` equal to the server's port, then the tunnel.
3. Pre-link check by the coordinator, through the public address, status codes and the sha256 of the page body only, the key read from its file and never echoed: no cookie 403; a wrong key 403; the key 302 with `Location: /?practice` and `SameSite=Lax`; with the cookie, `/key.json`, `/BUILD.json` and `/labels_R2.jsonl` 404; a POST with an empty body (no Content-Length) to a path other than /save 403; with the cookie, GET `/?practice` 200 with a body whose sha256 equals the pinned page (pair.html 1dde2ecf… for Paper B, rater.html 84a90787… for Paper A). No other request: none to `/state/`, `/save`, `/assignment.json`, `/practice.json` or an image. The cookie file is deleted after the check.
4. The start line is written as ruled (CC-367 L-f with CC-397 W2 for Paper A; for Paper B the start line of CC-397 N5 after the GATE-SERVE line) and adds: the check of step 1; the server's pid and its command line from `/proc/<pid>/cmdline` (showing `--annotator R2`, the R2 directory and the port); after start, the listeners in 8790–8799 and 8890 are exactly the server's port and 8890 (8795, the PI's answer page, is named if up; the gate cannot target it); the gate's sha256, pid, `--target` and log file; the key's sha256 (never the key); the cloudflared sha256 and pid; the results of step 3. On a later session the start line gives `wc -l` and sha256 of R2's files, equal to the last session-end line, instead of "absent".
5. The coordinator gives the PI one link (address plus `/?k=<key>`), which opens the practice round. For Paper A, the PI first sends the card of CC-397 ruling 3, exactly as saved (its sha256 in the start line), in a message of its own; the card is never sent for Paper B. The PI then sends the link privately, without a link preview where the app allows, inside message M1 below, unchanged. When the rater reports the end of practice ("Xong vòng làm quen"), the coordinator checks `wc -l` of practice_R2.jsonl (at least 8 for Paper B; for Paper A at least the number of questions in the committed practice.json e0ed805b) and, in the first session, `test ! -e labels_R2.jsonl`; then the PI sends the main address (address plus `/`) inside message M2. In a later session the link again opens practice, which at once shows its end message; the PI then sends M2.
6. During the session the PI answers a question only by pointing to the on-page instructions ("Xem phần 'Cách trả lời' trên trang") or, for Paper A, the card. He does not watch the rater's screen (no screen sharing, no video call while R2 rates), does not open the link or the address himself, does not forward them, and sends no other file, image, caption or information about the study. No agent sends any request through the tunnel except the check of step 3.
7. Stop rule: if the page does not load, the header does not read "Người gán: R2", or the red warning stays for more than a minute, the PI asks the rater to stop and the coordinator ends the session (step 8); M2 is not sent until the cause is found and logged. If labels_R2.jsonl exists before M2 was sent: stop, open nothing, go to a judge (CC-367 ruling 6).
8. At the session end (the rater tells the PI, the PI tells the coordinator): tunnel, gate and rating server are stopped by pid, in that order, and the key file is deleted. The session-end line is written as ruled (CC-367 L-g; plan §6) and adds: `ss -ltnH` nothing on 8790–8793 or 8890; no cloudflared or gate process; the gate log's line count and its counts of `key-wrong 403`, `403-no-cookie` and `POST … 403` lines (step 3 lines included); the cloudflared sha256 (unchanged).
9. No other rating session, the PI's included, starts while a gate or a tunnel process runs.
