## 5. Verifier protocol (frozen)

- Question: `Is there {np} in the image? Answer yes or no.` With the image: '<image>\n' + question. Without: question alone, pixel_values None (model.chat's pure-text path).
- `{np}` comes from the frozen English map in the JSON (`verifier_protocol.english_class_map`): 112 entries, one for every class `rescap.chair.objects_in` can return.
- Image: the README's load_image / dynamic_preprocess at the pinned revision, input size 448, 1 to 12 tiles plus a thumbnail, ImageNet mean/std, bicubic resize.
- Prompt: the model's own conversation template and default system message, built exactly as model.chat builds them at the pinned revision.
- Score: one forward pass, no sampling: at the first answer position p = P(Yes)/(P(Yes)+P(No)), where P(Yes) sums the next-token probabilities of the first token of 'Yes' and of 'yes', and P(No) those of 'No' and 'no' (scripts/probe_existence.ask's rule for có/không).
- Cache: one JSONL row per item {image_id, class, np, p_with, p_without}; its sha256 goes into the job's sha file before any AUROC is computed.
- Memory: if these settings do not fit on the card the job stops; any change (e.g. fewer tiles) is a deviation filed and committed before the job restarts; no score made under other settings is used.
- No fallback verifier (§11).

## 6. Analysis

### 6.1 Items, labels and cells

- every (image, class) whose class one of the 13 pool captions names (plan_f1.items); y = class in ktvic5 gold (plan_f1.labels).
- v = share of the 12 samples naming the class; g = 1 if the greedy caption names it; cell = round(12*v)*2 + g (the knn_prior_eval convention).

### 6.2 G0, the gate

- A_within = knn_prior_eval.cell_auc(p_with, cell, y) over the N13 items: positive-negative pairs pooled over cells, ties count one half.
- A_noimg = plan_f1.auroc(p_without, y): marginal AUROC over all N13 items, ties averaged.
- The plan's 'no-image AUROC' is the marginal AUROC of the no-image score: R14-3 states its no-image reference point as a marginal AUROC (scripts/probe_existence.py), and a no-image threshold above the within-cell one is coherent only for a different statistic. The within-cell no-image AUROC is reported, not gated.
- Reported, not gating: cell_auc(p_without, cell, y); plan_f1.auroc(p_with, y); all four statistics on the N7_T0.5 sub-pool (greedy + 6 T0.5 samples; cell = round(6*v)*2 + g); item and pair counts per cell.
- 95% CIs: image-clustered percentile bootstrap over the dev images, B = 2000, numpy default_rng(0); reported; the gate uses point estimates.

### 6.3 Dev readout of XV-EF1 (secondary; only if G0 passes)

- Pool: N7_T0.5: greedy + 6 samples at T* = 0.5 (UPE-MBR's registered T* and pool size).
- Rule: XV-EF1 = the UPE-MBR rule with q_o = p_with(o): U(c) = upe_mbr.utilities base (self-MBR + retrieval CIDEr-D, train-minus-dev300 references) + LAM*10*EF1_V(c), EF1_V(c) = 2*sum over o in M(c) of p_with(o) / (|M(c)| + EG); upe_mbr.pick keeps the greedy caption unless another wins by more than MARGIN.
- COUNT control: upe_mbr.count_matched: q_o = 1, lam on COUNT_GRID matched to XV-EF1's mean classes per caption, ties to the smaller lam. XV-EF1-noimg: the same rule with p_without, with its own COUNT match (prior-leak control).
- ΔF1 vs COUNT: object_prf.paired(COUNT rows, XV-EF1 rows): ktvic5 gold, exact classes, n 5000, seed 0.
- ΔCHAIR_i vs COUNT (x100): CHAIR-vi against the 5 KTVIC references (upe_mbr.chair_delta); CI from the image bootstrap above.
- ΔCIDEr vs greedy: per-image word-level CIDEr-D (DF over the dev reference sets) through rl_reward.boot (b 2000, seed 0).
- Panel ΔF1 vs COUNT: object_prf.paired on the 296 panel images.
- Also reported: dP, dR; share of images switched from greedy; classes per caption; the same endpoints for XV-EF1-noimg.
- Frozen UPE constants: LAM 2.0, M 5, MARGIN 0.5, EG 6.0, RETRIEVE 10, K_SAMPLES 6; COUNT_GRID from 0.0 to 3.0 (61 values).

## 8. Gate, kill rules, carry rule and consequences

- **G0:** PASS if A_within >= 0.58 and A_noimg <= 0.60 (point estimates); otherwise KILL.
- On KILL: XV-EF1 is killed: no dev readout, no S4, no S6, and no test pool is ever scored with this verifier; reported as a pre-registered negative.
- Kill rule: G0 fails: A_within < 0.58 or A_noimg > 0.60.
- Kill rule: prior leak (dev readout): dF1(XV-EF1 - COUNT) > 0 and dF1(XV-EF1-noimg - COUNT_noimg) >= 70% of it.
- Carry rule: XV-EF1 enters the single final stacked-system prereg (PD-9 Q4) only if G0 PASS, no prior-leak kill, and on dev300 (point estimates) dF1 vs COUNT >= +0.5, dCHAIR_i x100 vs COUNT <= −1.0, dCIDEr vs greedy >= −2.0 and panel dF1 vs COUNT >= −0.5; otherwise it is not carried and the result is reported. Source: manuscript/research_r14/R14_3/REPORT.md prereg sketch (its test endpoints and guards) used as a dev carry rule; this is never a claim.
- Downstream: S6 may be proposed, with its own prereg, only if G0 PASS (PD-9 Q3); S4 needs G0 PASS and an S3 DPO-arm PASS (R14 synthesis Stage 2). Every Stage-2 item must start by 2026-11-05 (PD-9 Q3).
- Results are used only if the registered gate passes (GPU_JOB_PLAN_v1). Plan estimate 1.5 GPU-h for 2612 verifier forward passes; the plan figure includes R14-3's test-seed queries, which this job does not run.
