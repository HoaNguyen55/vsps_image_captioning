## (b) Overlap risks (max 5)

1. **ProVision (arXiv 2024/25) + CompCap (ICCV 2025): "factual by construction" synthetic text from structured units.** A reviewer may say "template-rendering from structure is known". Contrast: they *trust* the structure (a scene-graph generator, or chart metadata). VSPS verifies each typed unit with three states before rendering, neutralizes UNCERTAIN content, and records span ← proposition ← verdict. Say "first to render from *verified* propositions", never "first traceable synthetic captions".
2. **Entity-Faithful Repair / ReCap (ACM MM 2026): entity-level faithful repair of caption supervision plus down-weighting.** C1 medium. It is new, in an ACM venue, and not in any novelty file. Contrast: detector-binary, English, zero-shot captioning with synthetic images, rewriting existing captions. VSPS is gold-free construction with typed propositions (not only entities), K=5 dual-query votes and UNCERTAIN handling.
3. **ScaleCap (2025): question-driven enrichment plus sentence-level hallucination removal → a training set.** C1 low-medium. Contrast: sentence-level contrastive scoring, not per-proposition verdicts; there is no traceable rendering.
4. **RICO (EMNLP 2025): recaptioning that targets both accuracy and completeness.** A reviewer may ask "why not RICO-style recaption, then SFT?" Answer: it needs a T2I model plus iterative MLLM diffing, which is infeasible on one 3090 for Vietnamese, and it keeps no claim-level record.
5. **Celona et al. (Springer NCA 2025): multi-captioner LLM fusion in a journal.** Low overlap, but it is the reference a journal reviewer reaches for if VSPS adds multi-source proposal fusion (§d #4). Position VSPS's fusion as "union of proposals → verification", not "LLM merge".

## (c) Must-compare baselines / must-cite (max 5)

1. **ProVision** (+ CompCap in the same sentence): the structured or programmatic synthetic-data precedent for C4.
2. **Entity-Faithful Repair (ACM MM 2026)**: the newest C1 neighbour.
3. **Precision or Recall? (Findings EMNLP 2024)**: empirical justification for precision-first targets. It turns H5 (recall cost) into a design choice backed by prior evidence.
4. **PixMo-Cap / Molmo (CVPR 2025)** and **PerceptionLM (2025)**: the two open SOTA dense-caption engines. Hallucination control is human-anchored in PixMo and prompt-only in PLM; neither verifies claims.
5. **Baseline-type comparison**: "zero-shot Qwen2.5-VL-7B captions → SFT" (distillation without verification, the ShareGPT4V/LLaVA-OV recaption recipe on KTVIC train). If the existing P2 "unverified SFT" baseline is exactly this, name it as the recaption-SFT baseline in the text. If not, it is the one cheap baseline a 2026 reviewer will expect (one SFT run of about 3 seeds).

## (d) Actionable improvements, ranked by expected gain / cost

Context: the target-side ceiling is the bottleneck (funnel: SUPPORTED 48.0, then supervision 42.5 after D8; the model reaches 37.1 on test). Richer *rendering* alone cannot add objects that never enter P*. #1–#3 make the targets richer and more fluent without losing traceability. #4 is the only one that adds new objects.

### #1. Coverage-guarded constrained-LM fusion for all 3,560 detailed targets (fixes H6 fluency at no recall cost)
- **What:** in `rescap/pipeline/realize.py`, after `enforce_grounding` in the constrained-LM branch of `realize()`/`_realise`, add an acceptance test. The LM text must realise every proposition the template realises: `stats.unrealised_ids` is empty, and the CHAIR objects of the text (`objects_in`, already imported) contain the CHAIR objects of `realise_template(plan)`. Otherwise fall back to the template. The D8 −1.1 recall from the 630 LM rows is exactly this failure: the LM merges or drops entities. Also put the entity-coverage rule into the §6.1 prompt (`PROMPT_REALISE`): "mỗi thực thể trong danh sách phải được nhắc đúng một lần". Then run `scripts/constrained_lm_pilot.py --n 100`, check the fallback rate and run `scripts/recall_funnel.py`, and only after that render all 3,560 detailed rows.
- **Effect:** recall = template (by construction), precision and hallucination unchanged (spans are still enforced), and fluency up (the template repetition in row 6482 disappears). It removes the 650/3,560 inconsistency the paper must currently explain.
- **GPU cost (RTX 3090):** text-only Qwen2.5-VL-7B (4-bit) calls of about 150 output tokens, up to `max_retries` per image. Estimated 2–5 h for 3,560 images; measure with the pilot first. Then SFT retrain with 3 seeds.
- **Risk:** low. The worst case is a high fallback rate, which just means "same as now".

### #2. Multiple traceable renderings per image (data augmentation without new claims)
- **What:** the PixMo multi-transcript, LaCLIP-rewrite and DreamLIP sub-caption sampling idea, restricted to verified content. For each image emit R=2–3 detailed targets from the same P*: (a) template with `style_variation=True` and different `seed`, (b) constrained-LM (#1), (c) a different planner order (entity-first vs scene-first). Each rendering keeps its own span record. Implement as a loop in the script that writes `sft.jsonl` (`scripts/clean_supervision.py` / `build_dpo_data.py`, where `realize()` is called), with a `renderer`/`rendering_k` field. Keep total SFT steps fixed (subsample) so the cost does not triple.
- **Effect:** less memorization of template openers ("Có một…"), better fluency, and possibly +1–2 recall at test. When targets disagree in order, the model is less inclined to stop after the first few entities (an EOS effect; see Less-is-More / Devil-in-EOS). Hallucination is unchanged (all renderings come from the same P*).
- **GPU cost:** rendering is the same as #1 per variant (template variants are CPU-only). SFT at equal steps is about the same as now.
- **Risk:** low. The main risk is no measurable change in recall. Report fluency (human 1–5 on 50 images) as the outcome.

### #3. Budget-conditioned targets + prompt hint (a controllable P/R knob; PixMo length hint)
- **What:** build detailed targets at several budgets from the same verdict store: B ∈ {5, 9, all-SUPPORTED-entities} (selector in `rescap/pipeline/select.py`, `SelectionConfig`), and put the budget in the prompt ("Mô tả chi tiết … (khoảng N ý)"). At test time, sweep N. The `select_entity_first.py` variant fits the "all" level.
- **Effect:** one adapter gives a P/R curve instead of a single point, which answers R1's recall complaint directly. Expect the high-N setting to move recall toward the target-side ceiling (about 46–48 on supervision) at some precision cost, and F1 may peak above 39.3. Every target is still verified, so the Less-is-More risk ("details beyond perception") is limited to verifier false positives (the audit shows 25.4% of SUPPORTED are wrong).
- **GPU cost:** selection and template are CPU-only; SFT costs about the same at equal steps; evaluation is 3 inference passes on the test set.
- **Risk:** medium. The model may ignore the hint without enough examples per budget level (PixMo uses a numeric length hint; a numeric hint is safer than words).

### #4. Multi-source proposal fusion → existing verifier (the only lever that adds objects)
- **What:** add proposals from independent sources, then **verify, do not merge**. Sources: (a) the zero-shot Qwen2.5-VL-7B caption on train images (R 57.1 on test), parsed to entity propositions with the existing lexicon/`objects_in`; (b) ScaleCap-style targeted object questions ("Trong ảnh có X không?") for lexicon objects that co-occur with SUPPORTED entities; (c) optionally, Patch-Matters-style crop captions (2×2 crops) for small objects. Feed only **new entity propositions** into `rescap/pipeline/verify.py`. Record `source` in the proposition, so traceability extends to provenance. Additional idea (needs calibration on `data/annotations/audit/tn.json`): cross-source agreement (≥2 sources) as an extra feature for UNCERTAIN entities, admitted only as hedged ("có vẻ như"), never as SUPPORTED.
- **Effect:** attacks the proposal and verifier losses in the funnel (all-props R 68.9, SUPPORTED 48.0). A plausible gain is +3–6 data-recall points if new entities verify at the current rate; this is unmeasured, so pilot it on 300 images with `recall_funnel.py`. Precision depends on the verifier (the 63.1% human-correct rate applies).
- **GPU cost:** the zero-shot Qwen captions for about 3,700 train images take ~1–2 GPU-h. Verification is the expensive part (~80 s/image for a full proposition set with Vintern-1B, K=5 dual). New-entity-only verification (~3–5 props/image) is estimated at ≤ 15–20 s/image, i.e. about 15–20 GPU-h for 3,700 images. Run the 300-image pilot first (~1.5 h).
- **Risk:** medium-high. Source (a) is the same model family as the generator (H2 correlation). Agreement-based admission can inflate CHAIR, so keep it hedged-only and report the result separately.

### #5. Span-level loss weighting from verdict margin (uses traceability, which nothing else in the literature can)
- **What:** Entity-Faithful Repair down-weights unreliable *samples*. VSPS can weight *tokens*, because each span knows its proposition and K=5 vote fraction. Store `spans` (char offsets + support fraction) in `sft.jsonl` (the realize `caption["spans"]` already exist and are dropped when the file is written). In `scripts/train_stage2.py`, map char offsets to token offsets (tokenizer `return_offsets_mapping`), set a per-token weight w = f(support margin) (e.g., 1.0 for 5/5 votes, 0.5 for 3/5, 0.3 for hedged spans; connectives 1.0), and override `compute_loss` with weighted cross-entropy.
- **Effect:** lower hallucination from verifier false positives (the 25.4% wrong SUPPORTED are likely concentrated at low margins; check in `tn.json` before building this). Expected recall roughly neutral. It is also novel enough to be a contribution claim ("verdict-weighted SFT").
- **GPU cost:** same as a normal SFT run (3 seeds, about the current training time).
- **Risk:** medium. It needs margin↔correctness correlation in the audit (check first, with zero GPU), and a custom loss adds code to maintain.

### #6. EOS-debias / min-length decoding on the trained adapter (zero training)
- **What:** in the evaluation path (`scripts/evaluate.py` / `render_vsps_preds.py`), sweep a small EOS logit penalty or `min_new_tokens`. Devil-in-EOS shows that this raises detail, with hallucination rising.
- **Effect:** probably + recall and − precision. It is cheap evidence on whether the trained model "knows more than it says" (if recall rises with flat precision, the targets are too short, which argues for #3).
- **GPU cost:** about 1 h of inference on the test set per setting.
- **Risk:** low; it is diagnostic only.

### #7. Matched-budget evaluation of supervision and outputs (paper quality, no GPU)
- **What:** following arXiv:2610.00952, truncate or compare the zero-shot and VSPS captions at a matched token budget (e.g., the first 64 tokens) and report CHAIR, P/R and hallucinations/caption at equal length. Add it as an option in `scripts/object_prf.py` / `score_ci.py`.
- **Effect:** pre-empts the "VSPS hallucinates less only because it is shorter" objection. No change to the model.
- **GPU cost:** none.
- **Risk:** the result may show that VSPS's advantage shrinks at matched length. It is better to know before reviewers do.
